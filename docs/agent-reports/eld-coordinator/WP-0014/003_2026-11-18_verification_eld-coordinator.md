# WP-0014 / 003 · Why three sentences took 54 seconds

**Accept the diagnostic and qualify one resident native OCR worker per GPU.** The current app starts a process, verifies the model files, loads the model, and pays the first-inference cost on every document. On Jack’s RTX 5070 Ti, a prototype that reused the verified model returned two different short scans in a median **6.650 seconds** once ready. An independent repeat returned the same scan in **6.851 seconds**, with exact text. In the browser, a saved result appeared **10.243 seconds after Extract** with a ready worker, compared with **52.604 seconds** on the shipping path. ## Where the wait went

Jack’s original receipt records **53.374 seconds inside the worker**. Loading took 12.261 seconds, rendering 0.182 seconds and synchronized inference 26.808 seconds. The remaining 14.123 seconds fell outside those timers. The matching database record shows only 0.020 seconds between queue and claim. The original receipt has no first-token or browser-frame clock. We kept the private document on the workstation and used synthetic scans for every new inference. [Original receipt reconciliation](../../../coordination/WP-0014/host-and-original.md)

A separately instrumented cold process reproduced the symptom and exposed recurring costs. It spent 6.445 seconds verifying and pinning the model and notice files, 4.625 seconds importing Torch and Transformers, and 11.737 seconds loading the tokenizer and model, including transfer to the GPU. Its first token took 18.695 seconds from native generation start. On four ready short calls that fell to **0.376–0.435 seconds**. After the first token, the model emitted roughly 9–10 visible tokens per second. Each short scan produced 57 tokens including layout markup, from 279 prompt positions including 273 image positions. The same dense fallback executed in all matched native trials. The precise operations responsible for the rest of the first-token delay remain unresolved. A separate CPU run measured 7.293 seconds to verify 6.699 GB of files. That measurement cannot retrospectively allocate the original 14.123 seconds. ## Correctness and operating limits

Both short scans preserved every sentence in order, with punctuation and case. The work order retained all 15 checked printed field values and 18 of 19 cells in their expected positions. Both paths read a `5` as `S` in the same SKU. Removing only coordinates yielded identical paired outputs. Warm A moved one box edge from 103 to 104, independently reproduced, and 15 of 36 work-order boxes changed. All seven browser jobs reopened with the correct original, attempt and review history. The independent reviewer checked 21 database transaction events. [Coordinator’s native artifact checks](../../../coordination/WP-0014/author-evidence-check.json) · [Independent structured audit](../../../reviews/WP-0014/eld-latency-reviewer/author-calculation.json)

The three roles completed 23 synthetic model calls under successive exclusive GPU leases. Nine measured native execution, ten exercised scheduling including three explicit warm-ups, and four independently repeated the decisive native comparison. All three leases were returned. The browser campaign observed at most one owned model process and sampled up to 9,136 MiB used on the shared 16 GB GPU. Two Intake openings shared one preparation. The crash-before-CUDA control saved no successful result, and an idle-stop request was refused while work was outstanding. The accepted supervisor has no cross-document batch or pre-render handoff. Production qualification must still exercise active decoding interruption, stale replies, actual idle deadlines, and restart. [Execution and lifecycle evidence](../../../research/WP-0014/scheduling/evidence/run.json) · [Shared-host sampling](../../../coordination/WP-0014/host-samples.json)

**The SGLang comparison remains open.** The pinned Baidu wheel requires `sglang-kernel==0.4.7`. Its published binaries are Linux-only. Windows binary resolution failed, AMD firmware virtualization is disabled, and no WSL Linux distribution or reachable Linux Docker engine was available. No SGLang model run occurred. The cited upstream hundred-page decoding benchmark cannot predict 0.5–1.2 seconds for this page and GPU. A GPU-capable Linux environment, with a matched native control on that environment, would allow a measured comparison. [Host checks, package evidence and upstream results](../../../coordination/WP-0014/host-and-original.md)

## Product decision and publication

Start preparation asynchronously when an operator opens Intake. Reuse one fully verified model and let a real queued document run first if separate warm-up has yet to start. Keep upload usable, check source and output identity per attempt, serialize requests, bound idle VRAM, and retain the current worker as a fallback. Keep cold Intake-to-result and ready click-to-result as separate acceptance measurements. The shipping app still starts a worker per document. The packet ends with this recommendation and a separately scoped product proposal. [Product proposal and acceptance cases](../../../coordination/WP-0014/product-proposal.md)
