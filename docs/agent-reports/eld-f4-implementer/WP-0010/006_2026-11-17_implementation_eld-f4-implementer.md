## Decisions and rationale

1. **Eliminating the `withComponentInputBinding` microtask race via synchronous initial `ActivatedRoute` sync + transient `NavigationBehaviorOptions.info`:**
   - Inspection of installed `@angular/router` `22.2.6` (`RoutedComponentInputBinder.subscribeToRouteData`) confirmed that after initial mount (`index === 0`), every subsequent query-parameter navigation pipes component input updates through an asynchronous `Promise.resolve(data)` microtask *after* `NavigationEnd`, which then schedules Angular's `effect()` asynchronously. In `c383021b`, `ArchivePage`'s `effect()` could not distinguish its own earlier `router.navigate` settling from an external history/link navigation and unconditionally ran `this.draftQuery.set(urlQ)`.
   - Reading `this.route.snapshot.queryParamMap` synchronously in `constructor()` (recording `initialNavigationId` to ignore the initial `NavigationEnd` without firing a duplicate HTTP call) and tagging self-initiated `router.navigate` calls with transient `info: { sourceComponent: this, commandSeq }` allows `ArchivePage`'s `Router.events` listener (`NavigationEnd | NavigationSkipped`) to recognize its own route completions synchronously while `router.currentNavigation()` is active:
     - Self-initiated completions never overwrite `draftQuery`, never reset pagination, and never trigger duplicate HTTP searches; if a stale `commandSeq < latestCommandSeq` ever committed out of order, `navigateForActiveState(latestCommandSeq)` re-asserts the authoritative URL.
     - Because `NavigationBehaviorOptions.info` is transient in-memory router metadata (never written to `window.history.state`, `localStorage`, or `sessionStorage`), external browser Back/Forward (`popstate`), header `routerLink="/archive"`, and external deep-links arrive with `info === undefined` and remain authoritative.
2. **Clearing `this.response` on new search execution:**
   - Setting `this.response.set(null)` in `executeSearch(...)` ensures displayed cards, source headers, and keyset `nextCursor` tokens always belong to the active `(activeQuery, selectedSource, pageNumber)` tuple and never linger next to a newer in-flight or failed (`400`/`503`) query.
3. **Separating controlled harness mechanics from real browser integration:**
   - In both [verify_search_navigation_edge.mjs](../../../implementation/WP-0010/eld-f4-implementer/search-navigation/scripts/verify_search_navigation_edge.mjs) and [archive.spec.ts](../../../../web/e2e/archive.spec.ts), pending route propagation is controlled deterministically in `ng serve` dev mode by attaching a Promise-latched `canActivate` gate (`runGuardsAndResolvers = 'paramsOrQueryParamsChange'`) to the live `/archive` route via `window.ng.getComponent`, while real HTTP queries execute unthrottled against PostgreSQL `18.7` + `.NET 10` API. Out-of-order HTTP `200`/`500` suppression is separately verified via explicit Playwright `page.route` Promise latches rather than sleep-duration assumptions.
