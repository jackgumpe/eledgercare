## Decisions and rationale

1. **Race-free Windows Job Object containment (`WindowsJobProcess.cs`)**: Assigning a process to a Job Object *after* normal `Process.Start` leaves a race window where a Python venv `Scripts\python.exe` stub can spawn its child interpreter before assignment. Launching with `CREATE_SUSPENDED | CREATE_BREAKAWAY_FROM_JOB`, assigning to an owned Job Object configured with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, persisting `(launcher_pid, launcher_create_filetime)` in PostgreSQL, and only then calling `ResumeThread` closes the race completely. Real GPU Scenario 3 confirmed kernel cleanup of both launcher (`PID 19740`) and CUDA worker (`PID 16036`) within `659.3 ms` of single-process `TerminateProcess` on API supervisor `PID 28180`.
2. **Isolated `-I` worker entrypoint & self-contained manifests (`F2-S1-01`)**: `python.exe -I` omits the script directory (`sys.path[0]`) in Python 3.12 (`safe_path`), which caused initial Trial 1 Attempt #1 (`7280463a...`) to fail in `1.13s` before model import. Prepending only `str(Path(__file__).resolve().parent)` inside `workers/local_ocr/run_worker.py` keeps external `runDir`, `PYTHONPATH`, and user-site off `sys.path` while keeping product code 100% independent of `qualification/`, `research/`, `evaluation/`, and runtime `git`.
3. **Monotonic fencing, explicit retry, and exact raw byte preservation (`F2-S1-02`, `F2-S1-03`)**: Every attempt acquires `nextval('eledgercare.extraction_fencing_seq')`, and `ExtractionStore` commits an `extraction_results` row only when `processing_jobs.latest_fencing_token == attempt.fencing_token` and the attempt remains `running`. `DiagnosticTextSanitizer` cleans `U+0000` and unpaired surrogates only in diagnostic `text`/`jsonb` columns while keeping accepted `extraction_results.raw_output_bytes` and `original_artifacts.bytes` (`bytea`) byte-for-byte unmodified.
4. **Honest preservation of `v2` helper assertion failure & `v3` read-only completion**: When `run_f2_author_runtime_v2.py` failed at the final Scenario 4 Edge check due to passing `"Interrupted"` instead of `"Extraction interrupted"`, the original `v2` summary was preserved unmodified as `FAILED` (`48e8896d...`), the GPU lease was returned immediately, and a separate CPU-only `v3` helper (`1bee2171...` / `88f24fb2...`) verified all 3 saved results and 4 attempts across PostgreSQL fast restart + disabled-OCR API & Edge reopen without executing any new model call or DB mutation.
