## Objective and acceptance criteria

Per [WP-0008-0009-authority.md](../../../coordination/WP-0008-0009-authority.md), [F3-review-correction.md](../../../design/F3-review-correction.md), [design/README.md](../../../reviews/WP-0008/eld-f3-reviewer/design/README.md), and [WP-0008-eld-f3-implementer.md](../../../kickoffs/WP-0008-eld-f3-implementer.md), observable completion requires:

1. **`F3-01` Source comparison (`F3-BIC-04`):** Two-pane route rendering readable native PDF content in Microsoft Edge alongside the five work-order fields, with page navigation and a visible download fallback; narrow same-origin `/preview` URL validation.
2. **`F3-02` Origin & immutability (`F3-BIC-01`):** Versioned conservative `work-order-suggestions/1` derived from persisted raw UTF-8 output; machine candidate status (`suggested`/`missing`/`ambiguous`/`invalid_or_oversized`) kept separate from human `decision`; immutable `document_originals`, `extraction_results`, and `machine_snapshot_json`; inert text rendering only.
3. **`F3-03` Explicit human state & history:** Append-only revisions (`1..128`) recording `draft` or `reviewed` status (`reviewed` forbidden when any field is `unreviewed`), explicit `unknown` + optional `unknownReason`, and selectable revision history where newer drafts never inherit prior reviewed approval.
4. **`F3-04` Concurrency, idempotency, & uncertain responses (`F3-BIC-02`, `F3-BIC-03`, `F3-BIC-05`):** Optimistic `expectedRevision` serialization (`23505` at `0`, `SELECT ... FOR UPDATE` on `work_order_review_heads` at `>=1`), `Idempotency-Key` replay checked before validation, stale-head, and `128`-cap checks (returning `replayed: true` and `isCurrentHead`), and strictly in-memory pending-save/stale-conflict browser reconciliation.
5. **`F3-05` Restart & disabled-OCR reopen (`F3-BIC-06`):** Real PostgreSQL `18.7` + API restart with `LocalOcr:Enabled=false` over attributed genuine F2 seeds (`SYN-WO-01` and `SYN-MP-01`), reopening exact review state, revision history, raw output, and original PDF bytes with zero model/GPU execution.
6. **`F3-06` Migration, privileges, & regression (`F3-KR-01`, `F3-BIC-02`):** Forward EF Core migration, `DeleteBehavior.Restrict` FKs, column-scoped `GRANT UPDATE` for `eledgercare_app`, and passing F1/F2 `.NET` and Playwright Edge suites on owned ports `5390`/`4410`/`55436`.
7. **`F3-07` Separation & honesty:** Zero product imports from `qualification/`, `evaluation/`, or `research/`, zero expected-answer lookups, zero fake OCR branches, and preservation of the accepted `workers/local_ocr/README.md` network-isolation wording (`83ed6624f95c48bfbae4c466201774824f63ef5e`).

## Decisions and rationale

1. **Strict Raw HTML Table Markup Guard & Conservative Five-Label Policy (`F3-BIC-01`, `F3-02`, `F3-07`):**
   - Existing [SafeNativeDisplayParser.cs](../../../../src/ELedgerCare.Domain/Processing/SafeNativeDisplayParser.cs) strips attributes when building display `TableRows`, so checking display cells alone would silently accept `colspan`/`rowspan` tables. Added `SafeNativeDisplayParser.TryParseStrictSimpleTableRows`, which inspects raw `<table>` markup on `ExtractedBlockView.Text` and rejects any attribute on `<table>`/`<thead>`/`<tbody>`/`<tfoot>`/`<tr>`/`<th>`/`<td>` (including `colspan`/`rowspan`), `<colgroup>`/`<col>`/`<caption>`, nested `<table>`, unbalanced tags, or non-2-cell rows.
   - [WorkOrderReviewSuggestions.cs](../../../../src/ELedgerCare.Domain/Review/WorkOrderReviewSuggestions.cs) implements `work-order-suggestions/1` directly in `ELedgerCare.Domain` with zero research/evaluation references: exact trimmed case-insensitive match against the five authorized label sets, rejection of `Label::` double-colon inline splits, rejection of 2-column header pairs where cell 2 is itself a recognized label, single immediate narrative block capture after the single matching heading (`issue_and_resolution`), `ambiguous` status with `competingSources` when multiple distinct values exist, and strict separation of machine `status` from human `decision` (`unreviewed` at revision `0`).
2. **Column-Scoped PostgreSQL Least Privilege & Concurrent Serialization (`F3-BIC-02`, `F3-04`, `F3-06`):**
   - In [grant-runtime.sql](../../../../deploy/dev/database/grant-runtime.sql), `eledgercare_app` receives `SELECT, INSERT` on all three F3 tables and **column-scoped `GRANT UPDATE (current_revision_number, current_revision_id, current_status, updated_at)`** on `eledgercare.work_order_review_heads`. Every immutable head column (`result_id`, `input_sha256`, `raw_output_sha256`, `profile_id`, `field_schema_version`, `suggestion_policy_version`, `machine_snapshot_json`, `created_at`) and every row in `work_order_review_revisions` / `work_order_review_fields` fails closed with PostgreSQL `42501` on `UPDATE` or `DELETE`.
   - Because `eledgercare_app` lacks `UPDATE` on `documents` and `extraction_results`, [WorkOrderReviewStore.cs](../../../../src/ELedgerCare.Infrastructure/Persistence/WorkOrderReviewStore.cs) serializes `expectedRevision == 0` via unique constraints (`23505` rollback + fresh `AsNoTracking` reconciliation for duplicate `Idempotency-Key` vs. stale head) and serializes `expectedRevision >= 1` via `SELECT ... FROM eledgercare.work_order_review_heads WHERE document_id = @docId FOR UPDATE` (permitted by PostgreSQL `18.7` under column-level `UPDATE` grant) followed immediately by a **post-lock `Idempotency-Key` recheck** so a concurrent duplicate retry never false-conflicts as `409 stale_expected_revision`.
3. **Replay-Before-Cap Ordering, Deterministic `request_sha256`, & Strict Input Validation (`F3-BIC-03`):**
   - [ReviewEndpoints.cs](../../../../src/ELedgerCare.Api/ReviewEndpoints.cs) enforces a `32,768`-byte request cap (`413 review_request_too_large`), rejects client-supplied provenance keys (`400 client_provenance_forbidden`), and checks `Idempotency-Key` replay **before** payload validation, `expectedRevision` stale checks, and the `128`-revision cap. Replaying an earlier revision after newer revisions exist returns `200 OK` with `replayed: true`, `isCurrentHead: false`, and `currentHeadRevisionNumber` so clients never overwrite newer head state.
   - [ReviewTextValidator.cs](../../../../src/ELedgerCare.Domain/Review/ReviewTextValidator.cs) rejects lone UTF-16 surrogates, C0/C1/DEL controls, bidirectional overrides (`U+202A..U+202E`, `U+2066..U+2069`, `U+200E`, `U+200F`, `U+061C`), newlines/tabs in single-line fields, and values exceeding field caps (`64`/`200`/`120`/`64`/`4000`, `unknownReason <= 500`, `operatorDisplayLabel <= 80`) rather than silently truncating or substituting characters.
4. **Readable Native Edge PDFium Two-Pane Layout & In-Memory Uncertain Reconciliation (`F3-BIC-04`, `F3-BIC-05`):**
   - `GET /api/documents/{documentId}/preview` streams stored PDF bytes (`enableRangeProcessing: true`) with `Content-Disposition: inline`, `X-Frame-Options: SAMEORIGIN`, `Content-Security-Policy: frame-ancestors 'self'`, and `X-Content-Type-Options: nosniff`. [pdf-preview-url.ts](../../../../web/src/app/review/pdf-preview-url.ts) validates `^/api/documents/[0-9a-f-]{36}/preview$` before `bypassSecurityTrustResourceUrl`.
   - In [work-order-review-page.ts](../../../../web/src/app/review/work-order-review-page.ts), independent pane scrolling (`overflow-y: auto` on `.fields-pane` rather than `position: sticky` on `.pdf-pane`) preserves Chromium's out-of-process PDFium compositor surface across field scrolling and full-viewport screenshots. No third-party PDF renderer was needed.
   - Pending edits and the active `Idempotency-Key` stay strictly in component memory (`0` `localStorage`/`sessionStorage`/`IndexedDB` calls), surfacing explicit `Retry exact save` and `Reload server state` actions on transport uncertainty or `409 stale_expected_revision`.
