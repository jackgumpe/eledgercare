# CPU integration interface

The fixture author exports UTF-8 JSON Lines cases. The stock author supplies a normal executable CPU analogue capture and read-only scorer. The reviewer runs both independently. A case describes a starting scenario and injection schedule, never the expected answer. The scenario generator can map fixtures to a documented native-sized or sparse little-endian FP32 storage representation; label byte offsets as dense token-ID offsets or compact physical offsets explicitly. Supply the map for noncontiguous vocabulary IDs. Keep claimed observations, independent ground facts and detected faults distinct. The scorer consumes only evidence and frozen contracts, never case names, injected fault types or oracle outcomes.

Use a neutral interchange file to connect the independently owned commands. The authors may refine transport together before exposing any expected or measured results. Freeze the final schema on both branches; any later schema-only translation must be generic, separately versioned, visibly reviewed and incapable of changing predictions. Evidence must exercise the normal recorder on the CPU analogue and normal read-only scorer. The challenge manifest, per-case oracle output, actual output and comparison are separate files. A runner must reject or retain unsupported/missing inputs explicitly and preserve valid conflicts even with other fields missing. No synthetic field may pass the native admission gate.
