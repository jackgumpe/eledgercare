# eLedgerCare | When should Windows OCR hand an identifier to Baidu?
Coordinator handoff · 2026-11-20 · approved research direction · packet number and release belong to eld-coordinator

**Objective.** Determine whether a visible identifier label is enough to route a useful, affordable subset of fields to ordinary Baidu. Use existing predictions to test the decision on CPU. Success earns consideration of a fresh timed experiment, never a production change. A negative result is a complete disposition.

## One rule, frozen before replay

Use the existing [WP-0019 label predicate](https://github.com/jackgumpe/eledgercare/blob/d62a96f8145345ce4c43544850d20fce13659879/docs/research/WP-0019/astra/policy.py) unchanged: it matches whole alphabetic tokens such as “ID”, “serial”, “inspection” and “reference”. **Only use its label predicate**, not its digit, crop, or column-content heuristics.

1. On frozen full-page Windows output, select body cells beneath a detected header matching the predicate, and non-table prose lines bearing a matching label. Select the field regardless of whether its value looks plausible, numeric, or empty. Unlabelled fields, unknown layouts and absent prose regions are not guessed. Include all candidates, including false triggers.
2. Write and hash the routing manifest using Windows observations alone: document, page, observed region, reason, and unique native three-page window. No answer keys, expected boxes, corrected annotations, case IDs, scored comparisons, crop disagreements or neural text enter this step. No hand-entered template for H or A. A non-author checks the input allowlist and can reproduce the manifest without the scoring directory.
3. Fetch **only archived ordinary Baidu results** for the selected windows. Before scoring, fix a deterministic, application-visible mapping: one native field or line, bound to the same page and observed region; declare coordinate convention, overlap criterion, tie/boundary behavior and value extraction for label-bearing lines. Use literal native values on uniquely bound fields; preserve the Windows result on missing, ambiguous, or unusable evidence, with an explicit unresolved reason. A native no-observation is never an empty string. No other field in a selected window may change. Freeze this mapping and substitution policy before viewing outcomes. Record binding coverage so that a rule that often declines to substitute cannot appear safer than it is.
4. Freeze predictions before joining any truth. Run the frozen scorer with the corrected title interpretation specified in advance; retain the original parser result separately if reported. Compare Windows-only, native-only and the frozen routed prediction at the same locations. Separate raw correctness from new review flags: flagging a wrong answer never counts as recovering it.

## What to return

| Question | Required evidence on H and A separately |
|---|---|
| Did routing improve reading? | Total critical fields; right→right, wrong→right, right→wrong, wrong→wrong. Show routed, substituted and retained/unresolved counts, exact field witnesses, damage to noncritical fields, legitimate spaces, and printed blanks. Reconcile totals. |
| Why did it succeed or fail? | For Windows-wrong/native-right opportunities: how many were outside the trigger, selected but could not be bound, or actually recovered? | Could selective routing plausibly save time? | Count unique pages and **distinct three-page native windows** requested versus all available, including windows bought for a single field. Use compatible per-window durations if available; distinguish observed component times from modeled serial Windows-plus-Baidu time, with explicit exclusions. Field counts are not GPU costs. No estimated rate may be published as measured throughput. |
| Can someone else reproduce it? | Pin archive identities, run orders, parser, candidate, rule, mapping and manifests. Preserve before/after archive integrity, scorer inputs and outputs, unmatched rows and any disagreement. Independent non-author reproduces the routing manifest, transitions and window count; coordinator records final disposition. |

**Decision rule.** Recommend a fresh timed trial only if there is at least one critical recovery, zero newly wrong criticals on each family, no damaged previously correct printed blank or legitimate spacing, reproducible bindings, and plausible cost within Jack’s 30-pages/minute target on the 60-page packet. At 30 ppm the total budget for 60 pages is **120 seconds**, including the Windows pass: use the matched archive clock and show what remains for Baidu. If timing is insufficient, report “cost unknown”; if even the measured necessary work exceeds that budget under the stated serial design, report “over budget.” Neither is a speed pass. This is a retrospective screen on exposed material: no fresh accuracy, field-call latency, production readiness or universal OCR claim. Do not change the rule to rescue it after scoring.

**Stop boundary.** CPU archive analysis and independent reproduction only. No new OCR, GPU lease, model downloads, training, product/UI edits, benchmark-key release or PGDA work. If the required frozen predictions, window mapping or file identities cannot be established, retain the partial receipt and identify exactly what is missing. A later hardware run would require a separate release on untouched forms.
