# WP-0024 external probe protocol

This is a CPU-only research probe. The only neural input is one ordered native B=1 window at a time. An input window contains the sensor's table-row and block records, including literal text, normalized boxes and pointers, and its contiguous little-endian FP32 pooled final activations of shape [spans, 1280]. The API projects the 4 box coordinates at 4 sinusoidal frequencies, giving 32 box features and a 1312-dimensional observation. No file path, binder ID, split, horizon class, stratum, truth, renderer coordinates, target position or twin identity is passed to a model. The process uses CPU FP32, one intra-op and inter-op thread and deterministic PyTorch operations. Run the pinned Q0 venv with CUDA hidden and the interpreter flags `-I -B`.

## Extraction gates and custody

The coordinator binds each finite B=1 release. H0 requires the separately generated unhooked and hooked full development pair to match every emitted ID through EOS and the promised source-to-token/final-state span mapping in each window. H0 failure stops live work before blind extraction. The development hook pair remains instrumentation-only. Corrected synthetic manifests in the custodian's v2 root at custody commit `7ae03a8fc60719f162552a4ccf218227fcb0f92a` provide separate dev_train and dev_cal splits. Each has 10 pairs and 20 binders across the two horizons and includes balanced and unbalanced histories. C1 separately checks fresh uncached paired extraction at 12 and 30 pages, including ordered rasters, prompts, model revision, capture layer, dtype, tokens, span map and pooled feature bytes, with a signed source-keyed cache plan and decision replay. Only frozen sensor features may be reused. Every arm starts each twin with a fresh state. Donor swap is the sole deliberate cross-twin matrix intervention. Canonical choice mismatches remain visible in all six arms' prediction records.

## Online state and scope

Ordered natural text lines `Owners:`, `Units:` and the two `Schema:` declarations on the first page seed candidates. Scope-sensitive active selections never enter this registry. The two directory-card line positions and candidate order carry no anchor information. Candidate equality evidence includes the complete ordered schemas and canonical choice arrays. Owner and unit anchors are observed strings. Column candidates are the second header in each directory schema, corresponding to the first numeric cell immediately after Item. Sorting by case-folded content and then literal text makes anchors independent of source position. The neural representation of a string uses signed boundary-marked character 1–4-grams, hashed with SHA-256 into 1312 bins, unit-normalized, conditioned only on field name and string. All arms consume the same online grammar. Feature-bearing table blocks are included in neural recurrence. Only individual table-row records generate header and target events.

The controller opens ledger, declares or amends unit, opens child at `Supporting schedule`, marks the active child as held on `Schedule subtotal:`, and pops a child on `Schedule closed`. A held child retains its frame and saved parent until the observed close. The active depth has eight slots numbered 0–7. Overflow, unmatched pop and unresolved child state abstain at a target. An ordered table header starts with Item. A target starts with Posting or MAINT-SUMMARY. Missing/multiple targets abstain. Literal target rows and cue pointers are retained. C0 truth is custody-only and evaluated after predictions freeze. M1, M2, M3-Zero and M3 separately record observed Window-1 declaration/header events and an audit-only root-frame read at the final Window-1 span, retaining the observed active depth and hold state. The audit explicitly selects root even if a child has already opened within Window 1. M2 exposes its saved header and M3 decodes candidates with its frozen readout and maps an unambiguous column back to the exposed schema. M1 uses the same query on its flat state, M3-Zero runs an actual disabled-matrix read, M0 records its structural suffix-only limit and M3-Swap attributes the original receiver state before the transplant. This read never advances an inference state. A frame or readout that fails to encode an exposed declaration remains an arm failure.

## Six views

- M0 receives canonical Page-1 strings and only the final window for decisions. Its symbolic decoder has no saved declarations.
- M2 retains typed frames. AMEND_UNIT replaces the active unit. A confirmed child clears its slot, transferring the observed child subtotal to the parent. On MAINT-SUMMARY it compares the visible first numeric cell with the observed saved subtotal as exact decimal numbers. A missing quantity abstains.
- M1 is a flat gated delta matrix with one 128 by 128 lane. M3 has eight such lanes. Both share the same initialized parameters, readout, candidate encoder, training labels, loss, epochs and calibration rule. The flat key spans all 128 coordinates, tying its last 32 to the query projection. PDS writes only to the first 96 coordinates. PDS protected owner/unit reads use coordinates 0–31 and column reads use 32–95. Summary reads use 96–127. Ancestor reads mix the causal prefix of active lanes with softmax of the observed depth indices. A summary reads only the active matrix. Both models read before writing the target span. The current span still provides the query.
- M3-Zero retains the same registry, learned projections, candidates and controller, and all matrices are zero throughout. A zero norm (at most 1e-8), tied best score or fewer than two candidates abstains. A safety/grammar failure can produce a more specific abstention first.
- M3-Swap snapshots both M3 states immediately before Window W, installs the other twin's entire matrix tuple and replays each receiving final window. The original and swapped runs share the very same receiver controller, candidates, depth/hold state, accumulated observations and target history by value. Fresh copies isolate each replay. Receipts bind both matrix and nonmatrix hashes, including the unchanged receiver's nonmatrix hash. Timings are excluded from the semantic digest and independently checked unchanged at transplant. Both original and swapped outputs retain all component scores. The output writer annotates the donor and receiver opaque IDs after both twins have completed every model decision.

The learned key is normalized, the value is linear, decay is sigmoid and beta is twice a sigmoid. M3 replaces only its active lane by the original delta recurrence. Pop computes four child invariants using the learned summary query, takes an unpivoted reduced QR wholly within the 32-dimensional summary coordinates and zeroes columns with |Rjj| below 1e-6. The parent update uses the equivalent low-rank residual on summary coordinates and copies the protected coordinates bit for bit. The child slot is zeroed. Rank-deficient QR keeps the exact forward result and stops the undefined basis derivative while gradients still flow through the value path. Both probes use the pop transformations and rank-four projection also as part of an identical residual candidate encoder, without adding memory to M1. The shared lexical gate has width 139 and a 128-dimensional output. Both have **880,258 trainable scalars**. The preflight includes nonzero finite gradients for every optimizer tensor in both probes, including the flat arm's shared candidate transforms.

## Training and threshold freeze

Training reads only the separate custody development labels under `private/train/truth.json`; calibration reads only `private/cal/truth.json`. The trainer rejects duplicate/missing binder-target mappings, overlapping binder IDs, wrong split sizes and unequal per-epoch binder-step counts. Both initialization and iterator order are identical between arms. Seed 2401, six epochs in the fixed manifest order, one optimizer step per trainable binder, AdamW learning rate 0.0005 and weight decay 0.01, gradient norm cap 1.0. Each uniquely identified answerable target supplies a mean of per-field cross-entropies on eight times the cosine similarities between the matrix response and canonical candidate embeddings. No missing label is inserted into the candidate registry. Missing target, ambiguous history, missing cue or out-of-registry field is recorded. T4 is a shared explicit ambiguity gate and contributes no gradient. Zero usable binder updates in any epoch, nonfinite gradients or unequal matched counts stop qualification. Training wall time excludes initial feature-file reads and calibration; the coordinator also measures total phase time.

The calibration grid uses top-1 cosine thresholds {-0.25, 0, .15, .30, .50, 1} and margins {0, .025, .05, .10}. Every non-null field must pass both thresholds with at least two choices and no exact tie. An arm's selection minimizes silent wrong binder postings, maximizes completely correct pairs, maximizes answerable binder postings, then maximizes cosine threshold and margin in that order. The same finite grid and priorities apply to both arms. Calibration compares non-null fields after HTML entity decoding, Unicode case folding and whitespace collapse. Literal markup stays part of a field. Null matches only null, including on a non-summary target. Any posting on an ambiguous target is silent wrong; abstention there is correct. Only typed postings and abstentions enter calibration. Predictions retain original literal spellings. The scorer remains a separately owned implementation. The resulting per-arm thresholds, complete calibration grids, weights hashes, data-manifest/label hashes and actual optimization counts go into the fit receipt. The coordinator binds its SHA-256 before blind prediction.

## Predictions, resource evidence and decision

The runner accepts ordered routing manifests shaped as `{"pairs":[{"twins":[{"binder":"opaque","target":"opaque","windows":["path/to/window", "..."]}, ...]}]}`. IDs are used solely for development-label lookup or for tagging already computed output. Each directory contains `metadata.json` with ordered `spans` and `pooled.f32`. The model API `predict_pair(m1,m3,thresholds,windows_a,windows_b)` accepts ephemeral in-memory window sequences. Fit with `run.py fit --train TRAIN --train-truth TRAIN_LABELS --cal CAL --cal-truth CAL_LABELS --output NEW_DIRECTORY`. Predict with `run.py infer --manifest ROUTING --weights FIT_DIR --fit-sha256 HASH --output NEW_DIRECTORY`. Outputs must use new directories.

Freeze `predictions.json` and `freeze.json` before opening any blind key. Each output is one flat opaque binder/target/arm record with a typed posting or abstention, source pointers and an event trace. The independent binding and subtotal diagnostics permit separate T3 analysis even if another component abstained. Full posting and failure evidence remains primary. Suffix-only and zero-state outcomes include separate subtotal measurements. Per-pair directional donor flip, retained receiver, collapse and mixed outcomes are custody-scored after freeze. The two-truth blind is 32 pairs, 4 matched 12-/30-page cases per stratum. Scoring, minimum C0 floors, safety vetoes, matched pair effect, 85% M2 coverage and replication-only ceiling follow the v2 PDF and later amendments.

Per-window timing uses monotonic CPU nanoseconds for actual warm cached feature-to-decision processing, excluding file reads, digest/swap auditing and post-hoc witness/diagnostic serialization. W1 audit reads are separate. Include mean pooled M3 latency over actual windows against 5 ms/window, per-window distribution, maxima, and the conservative result if audit/telemetry-inclusive timing is reported separately. The two swapped replay timing arrays reuse original measured prefix times for comparability and are not extra prefix execution. Record canonical candidate lookup times and actual counts per window. M2 records reachable live frame/controller/candidate/output bytes and audit-inclusive bytes separately. CPU-only probe device allocation is zero. Total extraction wall time, bytes read/written/reused, sampled whole-board VRAM including desktop, live extraction peaks and probe fit wall time remain separate measurements. No synthetic preflight runtime or extrapolation can stand in for a blind deployment or for a held gate.
