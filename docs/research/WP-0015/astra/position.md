# Read the pixels once and keep their coordinates

I would test the installed Windows English optical character recognizer as a changed-output challenger. It can return words with pixel rectangles from each source image. Recover rows and columns from image geometry, keep observed text and coordinates, and bind each result to its input digest and physical page. This removes Baidu's serial generation of both the transcription and layout markup. It also removes Baidu's learned layout interpretation, which could cost more correct pages than the elapsed time saves. My prediction is a win on clean printed prose and ruled invoices, with cross-page or irregular grids the likeliest reversal. There is no WP-0015 performance measurement in this position.

**Why this host.** In the previous ready-worker dense run, Baidu emitted 1,122 tokens in 118.670 seconds wall time. Its native clock measured 0.381 seconds to first token and 118.375 seconds across generation. One forward per token plus prefill was observed. The same engine took 6.650 seconds median on short prose. At the dense run's roughly 9.5 tokens/second, a page has a budget of fewer than 19 such tokens at the two-second research analogue of the customer floor. That calculation illustrates the size of the gap on one page. The observed twelve Triton attempts all returned `None`, with twelve dense starts. Neither an expert bandwidth bottleneck nor a fused kernel executing follows from these observations. **Implementation and comparator.** I checked the installed `Windows.Media.Ocr.OcrEngine` recognizer list and `en-US` is available, with `Windows.Media.Ocr.dll` version `10.0.26100.9278`. This is a native Windows option that needs no checkpoint download. Freeze its actual OCR assets and binary, compensate any bitmap resize in the returned rectangles, and charge recognition, structure recovery and durable writes. Disconnect evidence scoring from recognition. The control is the verified resident native BF16 `infer_multi` on the local Baidu revision `0480966938291445591f69f08a13b041c073a96a`, matching the existing prompt, greedy rule, no-crop path and token limits. For a boundary-sensitive packet send its complete bounded window to the control, retain its page markers and stop, and record exactly when page artifacts can first be published. Both arms start from the same PDF bytes and renderer. All generated IDs or source OCR word records, raw output and source references survive; the common scorer sees the same ordered page schema.

**Cheapest falsifier.** Use the three frozen development cases first. A complete clean prose page tests transcription and fixed overhead. The dense table stresses monetary punctuation, repeated values and correct physical cell positions. The multipage case stresses reading order, page provenance and continuation headers. Preserve failures and report all quality counts per packet. Pair the two arms in alternating order and repeat the decisive comparisons after a fresh warm-up. I would advance a research direction only if the measured complete-document gain beats paired-control noise and achieves at least a twofold speedup on a dense or boundary-sensitive case, with CER within +0.01, cell accuracy within −0.02, and no new unflagged critical error or wrong source. The twofold criterion is my investment threshold. A mixed outcome only supports a document-specific result. An independent held-out pair must reproduce any winner.

**Strongest objection.** A text recognizer can run quickly while assigning an accurate decimal to the wrong row, splitting a part number or silently dropping a header. Count a missing table against every expected cell, preserve blanks and unexpected detections, and inspect all new critical mistakes. Abandon an unattended route on the first wrong-source or unflagged critical error. Retain the baseline for a class that exceeds the quality budget. Carbon's full-target verified draft could keep difficult table relationships with near-identical outputs, but the pinned native loop uses mutable one-token `DynamicCache`, a page guard and a final-position LM head. Block verification must correctly implement per-position masks, page state and rollback; it merits a direct competing trial only if a working implementation can be frozen within the budget. A prompt-only compact Baidu output is another low-cost alternative if it genuinely lowers generated token count while retaining source relationships.

Research timing ends at verified durable publication of the complete document. Neither the shipping three-page worker nor archive/search latency is under test. Fresh 60-page and independent comparisons remain separate measured decisions.
