# WP-0030 author trace

Run the released commit from the assigned worktree using PowerShell. Supply a fresh run name for each pass.

```powershell
./docs/research/WP-0030/trace/run.ps1 -Candidate <full frozen author SHA> -RunName <released run name>
```

The launcher selects the packet's dedicated CPU-only Python environment and writes to `C:/Users/jackg/eLedgerCare-Speed/WP-0030/trace/<run name>/evidence/`. The entry point admits the same ten historical triples and authenticated Cedar opening through the pinned WP-0029 routing functions. Each arm loads its original CPU FP32 tensors once. Every member on every horizon starts with freshly allocated zero matrices and fresh controller, registry and attempts. All full-window projections use the same frozen function and window batch shape as the original probe. The final traversal ends with the posting write.

## Reading the evidence

- `M1-12.json`, `M1-30.json`, `M3-12.json` and `M3-30.json` each contain a JSON array with one paired observation per line. `step_index` counts completed writes. For the native pre-target attempt its pointer identifies the upcoming write, with the preceding count and actual current controller depth. `observation_index` counts reads, including the native attempt. Zero has no source pointer. The final post-write read uses the identical query retrospectively.
- `members.Alder` and `members.Cedar` retain each member's source, ordered events, eligibility, matrices/read fingerprints, scores, ties and ranks. The pointer is the one-based window, one-based window-local page and zero-based span index. Absolute pages are one-based. The source links to `sources.json` by RGB key and index. This catalog retains the archive revision/path, ZIP member prefix and hashes, ordered images, original span metadata with geometry and token indices, raw source bytes as UTF-8 text, and the digest of each contiguous 5,120-byte pooled FP32 feature. The metadata digest uses compact sorted-key JSON with ASCII escaping.
- `scores_f32le_hex` stores the two original four-byte scores in Alder, Cedar order. `margin` subtracts the Cedar score from the Alder score, and `delta` subtracts the Cedar-member margin from the Alder-member margin. Both subtractions use the original WP-0029 Python float arithmetic. The little-endian binary64 encodings accompany the decimals. Equal scores give both anchors rank 1 and no unique top owner. `owner_eligible` means the observed registry has exactly the two owner names. It is recorded separately from `scope_clear`, the native per-field thresholds and strict rank. Both names are scored even before registration.
- `parity.json` records both members' projected 128-component final queries in little-endian FP32 hex, original and observed score bytes, margins and native attempts. WP-0029 published query SHA-256 values. Each observation links to the full replayed bytes by that digest, and each member's three historical query digests are checked against those bytes. The original native attempt is checked across all field logit hashes, choices, flags, reason and typed output. Every historical checkpoint also has its state, read, owner columns, threshold flags, controller and pointer checked.
- `findings.json` contains both first positive responses, all strict paired wins, all exact zeros, each sign transition, each adjacent opposite-sign reversal, every decrease in absolute response, and every drop from a previously positive response. Transition records include both observations and their values. The first-after-owner search starts with the write immediately following the observed declaration. The row-level raw values cover both increases and decreases, including any pre-declaration changes. `runtime.json` records package versions, scratch command, source/data identities, CPU configuration, execution time and output hashes.

The two horizons reuse the same opening edit. Readouts localize score changes on these cached development trajectories. A textual cue and the pooled feature for an earlier span of the same jointly encoded input can have different relationships to that edit. A readout alone cannot isolate the underlying cause.
