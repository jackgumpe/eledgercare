# WP-0022 paired capture

The coordinator releases one exact candidate, custody/public manifest, scorer, release revision and unique raster count. Run `paired.py` with those values using the WP-0005 Python environment and `-B`. The scorer and truth are outside this capture program. To reproduce observations and decisions independently, read the frozen evidence and run the original reader against each archived observation.

The driver verifies working source bytes against the named Git blobs and exports public input files directly from the frozen custodian tree. Pillow decodes each PNG to full-resolution RGB at its declared density. Its independently computed opaque BGRA8 digest must equal the WinRT-decoded SoftwareBitmap before recognition. `input.json` records packed RGB row size. The raw payload records the actual WinRT plane stride and start offset, orientation-checked dimensions, returned alpha mode, native pixel format and decoder density. Every native line and word stays in API order including empty lines. Pixel rectangles are native `[X,Y,Width,Height]`. Projection converts their two corners to a 612 by 792 point top-left coordinate system at full precision. W includes literal native line text. R preserves renderer word references and point rectangles. Each page receives the single grid recorded against its input PNG digest.

Each unique PNG has a `captures/<sha256>/` directory. The grid-started and OCR-started files use exclusive creation before their respective calls. The Windows worker places raw output and the separate completion receipt in this directory before it exits. A started call with missing raw output terminates the driver. A repeated encoded raster is deduplicated. Distinct containers with identical decoded pixels stop input validation before either detector or recognition runs. `blind-hashes.json` covers all evidence JSON present at the prediction freeze, excluding itself.

## Timing boundaries

- `input.json/prepare` times source decoding, hashing and scratch PNG staging. `grid.json/detect` times only the original detector against the loaded RGB page. Both have Python process CPU and monotonic wall measurements.
- The x64 PowerShell worker starts cold on each unique page. `ocr-started.json` measures engine construction, resource checks, PNG decode, locked-plane inspection and pixel verification after script initialization. `raw.json` measures only the awaited recognition request. `ocr-finished.json` measures the worker from its in-script baseline through extraction of every native line/word and the durable raw write. These nested intervals have worker process CPU and monotonic wall measurements. `child-lifetime.json` measures the including-startup/exit wall interval and the waiting Python parent's CPU separately. Worker CPU excludes any charged to another process.
- Each timing/<arm>/<document>.json records point-observation assembly and the time the unchanged reader spends on each successive page inside one continuous document call. Process CPU timers on this Windows machine have coarse granularity. A zero reading means the measured interval did not advance the process counter. Python wall times use the high-resolution performance counter.
- For standalone arm costs, count the detector once per page per standalone arm. Add that arm's observation and reader cost. For W add the Windows capture cost once. The paired execution incurred each detector and Windows capture only once. Renderer generation is an offline custody cost. Disk evidence serialization and Git publication sit outside these stage totals.
