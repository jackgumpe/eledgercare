# Static four-window decode and gate contract

The controls freeze complete input pages, two independent parsers, and paired arm order. G1 changes grammar alone. G2 changes execution shape and kernel scheduling with the accepted grammar held fixed. CPU evidence is limited to deterministic token, plan and synthetic lane checks. The machine-readable thresholds are in [gate-contract.json](gate-contract.json).

## Input and scheduling

## G2 batch invariants

1. Pack four independent, contiguous three-page windows into each A wave. W0 has windows 0…3 and W4 has 16…19. Run five 12-page waves. In H use a real three-page row, a real one-page row and two inactive rows. An inactive lane has no associated page, no generated tokens, K/V writes or published output. Padded image/attention storage is internal. Every actual page retains its complete rendered field of view.
2. Preserve separate per-lane input IDs, visual embedding order, real prompt lengths, causal masks, page/image block masks, page-RoPE cursor, token position, emitted length, per-page limit, n-gram history, grammar state, stop state, output buffer and physical-page mapping. Use `last_hidden_state[b,prompt_length[b]-1]` for each unpadded/right-padded prompt. With packed flattening, carry explicit sequence offsets, select corresponding last real positions, and forbid attention or source-image leakage across lanes. Gather each lane's keys only within its committed prefix. Apply both local and selected remote key masks before normalization. Inactive lanes must have a finite dummy reduction or a predicated bypass to prevent NaNs leaking into other rows.
3. The native uncropped image layout contributes 273 tokens per page; each page marker contributes one. The prompt text encodes to 37460, 4366, 76466, 16. Including BOS, a three-page prefill uses 827 positions and a one-page prefill uses 279. The native profile permits 8,000 new tokens/page and up to 131,072 total positions. Preserving the three-page profile requires a capacity of at least 827+24,000 positions; with 32-token blocks use 24,832. Retaining all sequence lengths in a single Python scalar, selecting position_ids[0,0] for the batch, or reducing capacity to an observed trace length violates the contract. A storage optimization may change physical layout while retaining a proof of admissible capacity and identical indexing semantics. [Protocol](../../../../workers/local_ocr/local_ocr/protocol.py) · [Original engine](../../WP-0015/carbon/engine.py)
4. Prefill commits precisely each real prompt prefix. On each step select the next token once per live row. A nonterminal token is appended to the per-row output and, when a further forward is required, is written at that row's next legal cache index in each layer. Only then advance its committed length. A selected EOS ends that row, with no K/V commit for EOS or subsequent burst steps. A live row at its final legal slot cannot interpolate a fabricated stop. Finished and dummy rows use an absorbing EOS in scratch, retain their final lengths, histories and state, and perform zero writes into their persistent K/V, router keys and block summaries; repeated writes of the old value still count as writes. A predicated store or distinct scratch sink enforces this. A vectorized `where` followed by a store into the real dead row can preserve equality while violating the no-write requirement. Keep live-state counters independent of executing the fixed-shape arithmetic.
5. With 12 layers, 10 KV heads, 128 head width, BF16 keys and values and 128 FP32 router features, the layout above requires 6,102,712,320 B K+V, 610,271,232 B router keys and 19,070,976 B FP32 summaries. Together they use **6,420.1875 MiB** for B4. Count weights, vision/prefill activations, packed expert temporary copies, logits, masks, graph private pools, allocator overhead and CUDA context separately. A small control-run peak cannot establish headroom. Report observed allocated/reserved max, per-allocation sizes and device/process peak in MiB with sample cadence and device baseline. Use the packet peak limit on the agreed observed device measure, also publishing the other peaks and sampling limitations.
6. Packed expert routing and sorting must preserve each (row, token, top-k choice) index, weight and accumulation order policy. Invoke the supported grouped BF16 matrix multiply for prefill, account per-layer/per-wave calls, and require zero fallback. Stable buffer sizes, padded expert capacity and a device prefix sum avoid variable-output operators with hidden synchronizations. A static allocation sized to an average occupancy can overflow a single expert even when total capacity is sufficient. Freeze an exact worst-case bound or independent overflow-fail signal. Original Carbon selects a separate N=1 decode MoE path, uses a shared length per layer, grows its cache, falls back to reference attention for B>1 and copies token chunks to the host each burst. Simply setting B=4 cannot establish this design.
7. Capture the fixed multi-step (eight-token) decode burst plus DFA, original guards, MoE and sparse attention in the excluded warm-up, using fixed-shape tensor views and stable addresses. Every replay has a stable graph executable ID, stream, dtype, strides and pointers. Inputs, positions and liveness live in device memory. Reinitialize all logical state before measured use, including any warm-up scratch and guard counters. No host pointer/shape decisions or dynamic storage during replay. Packing/unpacking and host observations outside capture must be timed separately. A first-row EOS cannot short-circuit another active row. Any CPU decision to poll completion at a burst boundary is an explicit synchronized operation. To claim zero decode-path sync, use device-controlled continuation or a predetermined bounded replay schedule with absorbing states and defer the single completion read until the timed decode boundary. Include redundant inert replay work in wall time. If the implementation polls every burst, report the count and withhold the zero-sync claim. Multiple asynchronous host graph launch calls can represent one fixed replay schedule if no tensor value is read to choose the next launch.
8. Evidence must include capture count, actual graph replay count, graph/kernel trace, capture stream/pool IDs, before/after pointer inventory, allocation/free events, total/active/padded lane-steps, tail/post-EOS arithmetic, emitted/KV-committed counts by row/layer, grouped calls/fallbacks, and any decode-path D2H/synchronizations. Capture and first actual replay must both execute successfully on the pinned device. Collect a scoped CUDA runtime/API trace or comparably complete instrumentation showing D2H, syncs, event waits and launch boundaries; Python source scan alone cannot certify absence. Separate ordinary stream/event ordering from a host-blocking sync. Device counters and sentinel-poisoned dead regions test accidental reads and writes. Compare alone vs batched, permuted lanes, variable prompt lengths, immediate/mid/final-step EOS, all-dummy waves and a tail lane that outlives the other three, including a full reuse/reset of the same buffers. CPU toy controls model these invariants in part. Candidate-specific correctness and hardware traces are prerequisite evidence for the corresponding claims.

## Quality, latency and value

Each arm preserves per-window token IDs and raw output, pre- and post-grammar top choices for G1/G2, source PDF and physical-page/raster IDs, first-token/stop/page state, window failures, full projected prediction, and durable timestamps. For each real page count raw `<BLOCK>` occurrences, syntax-complete versus malformed/truncated/nested headers, out-of-range/reversed boxes, each parser's recognized headers, and table starts/closed/extracted/unmatched and extra cells. An empty output with zero malformed headers still fails page completeness and quality checks. Count table inventions against matched reference tables when the reviewer scores. Before scoring, a count disagreement with stored Windows geometry is an inspection flag only.

Report cold time from process/model initialization to ready, then ready wall from acceptance through PDF hash and render, model inference, projection, evidence writes and final durable prediction. Keep the original boundaries across arms. Report first durable page, window/model stages, complete pages, failed/fallback windows, throughput, warm-ups and operator intervention separately. Timing excludes warm-ups and scoring. A candidate's wall time cannot omit device completion, final copying or durable writes. For A let C_o denote original G0 Carbon ready seconds in order o; control spread is |C_AB−C_BA|. Show native spread too. With only two repeats this is observed spread, with no confidence interval or distributional generalization. For a cross-order speed claim give both paired ratios and the conservative min(control repeats)/max(treatment repeats); wins within control spread are inconclusive.

## Independent comparison with stored Windows predictions

Use only the registered, byte-pinned Windows predictions and matching timing on each identical H or A source, with page/RGB hashes verified and no new GPU or Windows inference. Freeze source path/commit, prediction digest, document clock and per-page identities in reviewer escrow before scoring. A uses 15.6546455 seconds. Use H's own matched clock when verifiable; otherwise report its transition counts and leave its rate unavailable. Apply both frozen parsers to each neural raw output. Windows keeps its existing word-box/table projection under both comparisons.

For every exact critical location, show (a) both correct, (b) Windows only correct, (c) neural only correct, and (d) neither correct. Include flags, changed wrong values, both-missed and wrong-source cases. For arm N versus Windows W, repairs = neural-only correct; regressions = Windows-only correct; net = repairs−regressions. Check net equals total correct_N−total correct_W. The signed marginal rate is net / (ready_seconds_N−ready_seconds_W), recording numerator, both times and denominator. At a zero denominator report the rate undefined. For a negative denominator state dominance or tradeoff directly since “per extra second” ceases to describe it; the signed quotient can be shown with its sign convention. Report gross rates and losses so an equal net cannot conceal errors of opposite sign. Repeat this matrix for each family, order, parser and measured neural arm, including G0. Distinguish all correctness transitions from the original scorer's new-or-changed unflagged predicate, which can catch a wrong→different-wrong at the same location. Never infer these pairs from aggregate error totals.

Record the raw top two FP32 logits, their IDs and difference at decision time before grammar, after the unchanged baseline guards, and the selected token/eligibility outcome. Bind these to raw token offsets. For truth-free retrospective identifier telemetry annotate mixed letter/digit spans (including internal hyphen) in the full decoded prose with their smallest pre-grammar top-two margin. State the span rule and show values/distribution; no calibrated error probability or confidence threshold is assumed. Keep punctuation, case and all competing raw tokens. Stored Windows table geometry can flag possible excess/missing tables and invite wider review. It cannot select a crop, mask prose, suppress a predicted table, overwrite a value, bypass a table-free page or route identifiers to a different model.

Selective neural allocation for mixed alphanumeric prose and tables, and padded contextual crops, are hypotheses for a separate benchmark after this gate sequence. The earlier roadmap also proposed asymmetric FP8 and self-speculation for WP-0017. Prioritization and execution of either direction require a subsequent decision.
