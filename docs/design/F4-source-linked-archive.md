## Customer behavior and bounds

An Archive route reachable from intake, result and review screens lists saved submissions and accepts a keyword query. A user can find a document through persisted machine text or its latest explicitly reviewed field values, see why it matched, and open the exact original page or review revision/history. Existing local synthetic one-to-three-page scope applies. Search is useful with OCR disabled and requires no new extraction. Existing accepted source/result/raw/attempt and review APIs remain truthful.

Empty query browses submissions, including pending/interrupted/failed extraction and documents without reviews, with honest status. A nonempty query searches text only in successful immutable results and eligible reviewed values; diagnostics, operator label, source hashes, raw internal IDs and unknown reasons are not searchable content. Original upload accepts PDF bytes with server-generated document names, so do not invent a user-supplied title/filename field. Use reviewed work-order/property labels when present and a short document identifier/date otherwise.

Three source filters: all (default), machine, reviewed. They select matching sources; no nonempty query result is claimed to match a source that did not contain the terms. With empty query, all lists all submissions, machine lists completed results, reviewed lists documents with an explicit reviewed revision. Include a clear empty/result/error state, search busy state, keyboard-labelled inputs and pagination. Keep internal full hashes/schema/IDs in existing secondary details.

## Revision selection and trust

For each document's single immutable accepted result, the reviewed search source is the greatest revision_number with status reviewed, not necessarily the current head. The latest reviewed revision replaces all older reviewed values for search, including removal of a prior value when the latest reviewed decision is unknown. Only accepted/edited nonnull field values are searched. Unreviewed drafts, unknown reasons, old reviewed values and saved machine suggestions are not substituted into this source.

If the current head is a newer draft, identify the matching reviewed revision/date and display "Newer draft exists." Opening a reviewed hit loads that immutable revision through existing history behavior; it does not overwrite the editable current head or call draft values reviewed. Original machine text stays separately searchable even when a human corrected it. A machine hit remains labelled "Machine extraction — unreviewed"; a reviewed hit identifies field label and revision. Human review is not factual certification.

A search response observes one consistent database snapshot for selecting documents, latest reviewed revisions, match reasons and snippets. A correction committed before a new request must be reflected immediately; in-flight snapshots may finish with their original pinned revision. Old links continue to resolve the pinned immutable revision and identify when it is historical. Do not cache reviewed values independently of transactional revision state in this first feature.

## Query semantics and response bounds

GET /api/archive accepts q, source, limit and after. q defaults empty; trim and split ordinary Unicode whitespace into at most8 literal terms, total at most160 UTF-16 code units and each term at most64. Reject NUL, lone surrogates and controls except accepted whitespace, unknown enum/duplicate parameters, invalid/oversized cursor or invalid limit with a stable400 response. A term is a literal substring, with case-insensitivity defined by the pinned PostgreSQL ILIKE/database collation; punctuation, %, _, backslash and leading zeros retain literal meaning. No regex, wildcard, Boolean operator, fuzzy or semantic syntax. Bind every term as a parameter and escape SQL LIKE metacharacters explicitly. Public help says all words must occur, order does not matter; tests pin case behavior and Unicode preservation in the actual database environment.

A document matches when every term appears in at least one eligible source unit for that document; terms may span pages or fields. all may combine machine and reviewed units, with every contributing source labelled. No AND matching across different documents. No hidden requirement that all terms occur in a single field. Exclude unsupported/truncated content silently from neither matching nor status.

Page size default20, maximum50. Deterministic document order submitted_at descending then document_id descending; keyset cursor binds last tuple plus normalized query/source, version, and strict length/format. No arbitrary SQL cursor content or credential/session key needed. Fetch limit+1 for hasMore; no expensive mandatory total count. Each page is a new snapshot; restart search to reflect newly changed membership. Unchanged data has no duplicate/skipped documents; changing reviewed values between requests is not a snapshot of the entire archive. Keep the query/filter in the URL and reset cursor when either changes. Ignore obsolete frontend responses after newer searches.

Return one card per document, at most one match witness per query term (max8), deduplicated where possible. Each witness binds machine result/page or reviewed revision/field and contains at most240 Unicode-safe UTF-16 code units around the literal match plus matched-term identity; clipping cannot split surrogate pairs. No entire raw output in the list response. Snippets and highlights are escaped text nodes/spans, never executable HTML from model/query. If fewer displayed witnesses than matches exist, say more matches are available by opening the document. A document matching terms across sources shows enough witnesses to explain every term.

## Persisted machine text and existing-data migration

Add a narrow production-owned archive projection over immutable accepted results. A projection is derived only from saved result bytes and the existing SafeNativeDisplayParser; never qualification/research/evaluation code. It retains result/document ID, raw SHA, projection version and honest physical-page/source-location metadata. Normal text blocks and table-cell text are searchable, preserving punctuation/leading zeros. Use plain table rows/cells for recognized tables rather than structural table markup. Unrecognized native blocks or malformed table content may be retained as inert raw extraction text with an explicit fallback flag. If physical page mapping cannot be established, provide a document-level fallback with no fabricated page coordinate. Do not silently discard a successfully stored result because its layout is unfamiliar. No inference or schema-field guessing is required.

Projection must be deterministic and bounded by existing16MiB raw result and1..3 physical-page ceilings, with bounded per-record allocation/iteration. Do not introduce arbitrary silent text truncation. Keep original bytes/provenance unchanged. A result with no searchable text still gets a completed projection marker, distinguishing empty from pending/failed initialization.

Prefer immutable per-result/page projection rows with explicit version and foreign keys. New result publication adds its projection within the same existing transaction that commits the accepted result/completed attempt. A failed transaction exposes neither half. Stale/fenced-out workers cannot publish projections. Search never reads diagnostic partial output. Runtime may insert/select projection rows, not update/delete them; retain every prior immutability grant.

Forward migration creates the new schema without rewriting existing originals/raw/results/revisions. An idempotent bounded initializer fills missing projections from saved immutable results before archive queries are available. Batch identity reads and process each bounded result separately; no entire archive/raw corpus materialized in memory. Readiness is explicit: either initialization completes before listening, or archive returns a clear retryable not-ready503 until complete, never a misleading empty successful search. On interruption, existing committed projections remain valid and restart resumes missing rows. Two initializers must not corrupt/duplicate or mistake a failed transaction for completion; use unique keys/transactional conflict reconciliation against raw identity and projection version. If an existing projection conflicts, surface a diagnostic failure without mutating original data or silently proceeding. Startup/initialization must work with OCR disabled.

The author chooses the smallest implementation consistent with these requirements and records query plans/resource measurements on a declared modest synthetic archive size. No added search service or dependency upgrade is needed. Do not claim large-archive scalability from small-fixture results. Use bounded cancellation/command timeouts and existing local-only protection.

## Source reopening and navigation

Machine hits link to original preview at the bound physical page and the saved result view; fallback opens document/result without a page claim. Reviewed hits open exact review revision and field, with source page link only when that field has recorded provenance. A human-entered value without source coordinates must not acquire fabricated coordinates. Validate route/query IDs, page1..document count and revision belonging to document before applying navigation. Existing same-origin preview construction remains; query content never supplies an arbitrary URL. Preserve current review edits/stale/uncertain-save warnings during navigation. Retain back-to-search query/filter state.
