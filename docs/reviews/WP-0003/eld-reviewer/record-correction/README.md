## 4. Honest Reassessment of Actual `PdfPigAdmission.cs`, `fetch_server_subset.py`, & Lockfile Scope

### 4.1 Actual `PdfPigAdmission.cs` Behavior & Focused Edge-Probe Disposition (`DI-07`)

[`PdfPigAdmission.Evaluate`](../../../../../src/ELedgerCare.Infrastructure/Pdf/PdfPigAdmission.cs#L19-L80) implements the accepted restricted developer-fixture admission profile (`bce84931:docs/design/F1-durable-intake.md` step 4) in six exact stages:
1. `HasSupportedHeader(span)` (`L83-L93`): Requires byte `0` to start with `"%PDF-1."`, minor digit `'0'..'7'`, and a PDF whitespace byte (`0x00, 0x09, 0x0A, 0x0C, 0x0D, 0x20`) at index `8`.
2. `EndsWithEofMarker(span)` (`L96-L105`): Strips trailing PDF whitespace from the end of `span` and requires the remaining prefix to end with `"%%EOF"`.
3. `StartXrefAddressesCrossReference(span)` (`L111-L145`): Calls `span.LastIndexOf("startxref"u8)` across the **entire** buffer (there is **no** 2 KiB scan window), advances with `SkipWhitespace` (`L147-L155`), parses an offset with `TryReadInteger` (`L157-L168`, reading `1..10` ASCII digits `'0'..'9'`), rejects `offset >= span.Length`, and accepts either:
   - `span[target..].StartsWith("xref"u8)` (`L126`), or
   - `<objNum>` (`TryReadInteger`) + `1+` PDF whitespace + `<genNum>` (`TryReadInteger`) + `1+` PDF whitespace + `span[afterGeneration..].StartsWith("obj"u8)` (`L132-L144`).
4. Opens `PdfDocument.Open(bytes.ToArray(), new ParsingOptions { UseLenientParsing = false, SkipMissingFonts = false, MaxStackDepth = 32 })` (`L40-L49`).
5. Rejects encrypted documents via both `document.IsEncrypted` (`L52-L55`, catching owner-password PDFs with an empty user password) and `catch (PdfDocumentEncryptedException)` (`L71-L73`).
6. Enforces `1 <= pageCount <= maxPages` (`L57-L61`) and calls `document.GetPage(pageNumber)` for `1..pageCount` without accessing `Text` or `Letters` (`L64-L67`); any non-`OutOfMemoryException` parse failure returns `PdfRejectionReason.Unreadable` (`L75-L79`).

Fresh continuation probes in `.scratch/reviewer-f1/record-correction/PdfGuardAuditProbes/Program.cs` (`11` cases, output in `pdf-guard-focused-audit.json`) combined with prior `ReviewerProbes` (`5` cases) and `PdfPigAdmissionTests` (`26` cases) confirm both the strengths and exact bounded heuristic limits of `StartXrefAddressesCrossReference`:
- **Verified strengths**: Admits valid >9.8 KiB PDFs where `startxref` sits >6 KiB from byte `0` and >3 KiB before EOF (refuting `/002`'s fictional 2 KiB window); admits valid PDF 1.5 cross-reference streams including compact `4 0 obj<< /Type /XRef ... >>` with no whitespace after `obj`; admits valid incremental updates while rejecting incremental updates whose **final** `startxref` is broken (`999999`); rejects `startxref 0` (`byte 0` is `'%'`, matching neither `"xref"` nor `<digit>`); rejects non-whitespace bytes after `%%EOF` (`MissingEofMarker`).
- **Documented residual heuristic boundaries (non-blocking within F1 contract)**:
  - Because `StartsWith("xref"u8)` and `StartsWith("obj"u8)` do not require a trailing delimiter and `PdfPig 0.1.16` retains internal `XrefBruteForcer` fallback even when `UseLenientParsing = false`, synthetic mutations where `startxref` points to a body indirect object header (`15` -> `1 0 obj`) or where `"xref"` is mutated to `"xreffoo"` pass the pre-check and are repaired by `PdfPig`; similarly, extra tokens between `<offset>` and `%%EOF` (unless containing literal `"startxref"`) are ignored after `TryReadInteger`, and wrong per-entry offsets behind a valid `startxref` are recovered (`PdfPigAdmissionTests.cs:210`).
  - `SkipWhitespace` does not skip `%...` PDF comments inside `startxref <offset>` or `<N> <G> obj`, and `TryReadInteger` reads at most `10` ASCII digits (sufficient for the `10,485,760`-byte 8-digit ceiling and standard 10-digit `xref` offsets, rejecting 11-digit zero-padded offsets).
- **Updated Disposition**: **ACCEPTED**. [`PdfPigAdmission.cs`](../../../../../src/ELedgerCare.Infrastructure/Pdf/PdfPigAdmission.cs#L7-L13) explicitly documents that F1 is a restricted developer-fixture admission profile rather than a hostile-content PDF validator, and all `DI-07` requirements are met.
