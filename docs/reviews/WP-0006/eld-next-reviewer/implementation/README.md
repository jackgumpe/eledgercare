### `F2-S1-01` (Blocking — `F2-01`, `F2-02`, `F2-06`): `workers/local_ocr/run_worker.py` crashes unconditionally at import (`ModuleNotFoundError: No module named 'local_ocr'`) under `LocalPythonOcrWorkerRunner`'s `-I` isolated invocation

- **Source Pins**:
  - [LocalPythonOcrWorkerRunner.cs](../../../../../src/ELedgerCare.Infrastructure/Extraction/LocalPythonOcrWorkerRunner.cs) lines `113`, `122`
  - [run_worker.py](../../../../../workers/local_ocr/run_worker.py) lines `1`–`10`
- **Mechanism & Empirical Reproduction**:
  `LocalPythonOcrWorkerRunner.ExecuteAttemptAsync` spawns `venv\Scripts\python.exe` with `workingDirectory = runDir` (`<WritableRuntimeRoot>\runs\attempt-<id>`) and `childArgs = ["-I", "-B", "-X", "utf8", "-u", workerScript, "--request", requestPath]`. Under CPython 3.12 isolated mode (`-I`, which sets `PyConfig.isolated = 1` and `PyConfig.safe_path = 1`), Python omits the script's directory (`workers/local_ocr`) from `sys.path`. Because `run_worker.py` executes `from local_ocr.worker import execute_request_file` at line `9` without adding `Path(__file__).resolve().parent` to `sys.path` (unlike `workers/local_ocr/tests/test_worker_cpu.py` lines `14`–`16`), every real child launch from `LocalPythonOcrWorkerRunner` terminates immediately with `exit code 1`, `ModuleNotFoundError: No module named 'local_ocr'`, no `envelope.json`, and validator outcome `worker_missing_envelope`. Reproduced directly via `LocalPythonOcrWorkerRunner.ExecuteAttemptAsync` in `Probe P2` ([stage1-verification-summary.json](stage1-verification-summary.json)).
- **Required Resolution**:
  Ensure `workers/local_ocr/run_worker.py` deterministically resolves its own `WORKER_ROOT = Path(__file__).resolve().parent` under `-I -B -X utf8 -u` when `cwd = runDir` (preserving `-I` isolation so `runDir`, user-site, and `PYTHON*` environment variables never enter `sys.path`), and add an end-to-end CPU subprocess test invoking `LocalPythonOcrWorkerRunner.ExecuteAttemptAsync` / `run_worker.py` with exact production CLI flags and an external `runDir` so the C#-to-Python envelope round-trip is exercised prior to GPU Stage 2.

### `F2-S1-02` (Blocking — `F2-04`, `F2-05`, `F2-06`, Transient Filesystem Guard & Supervision Containment): `LocalPythonOcrWorkerRunner.CheckStorageBounds` throws on transient cache subdirectory churn, `ExecuteAttemptAsync`'s `finally` skips `TerminateAllInJob` on loop exceptions, and same-instance `ReconcileAbandonedAttemptsAsync` wedges orphaned `running` rows

- **Source Pins**:
  - [LocalPythonOcrWorkerRunner.cs](../../../../../src/ELedgerCare.Infrastructure/Extraction/LocalPythonOcrWorkerRunner.cs) lines `122`, `154`–`247`, `409`–`442`
  - [ExtractionAttemptCoordinator.cs](../../../../../src/ELedgerCare.Application/Extraction/ExtractionAttemptCoordinator.cs) lines `31`–`38`, `129`–`145`
  - Compared against [env_guard.py](../../../../../workers/local_ocr/local_ocr/env_guard.py) lines `131`–`141`, `204`–`235`
- **Mechanism & Empirical Reproduction**:
  1. *Transient filesystem guard comparison*: Python's `env_guard.directory_size_bytes` (`os.walk(root, followlinks=False)` + `except OSError`) and C#'s `TryReadHeartbeatFile` (`FileShare.ReadWrite | FileShare.Delete` + `catch (IOException | JsonException | UnauthorizedAccessException)`) survived `200` rapid `heartbeat.json.tmp -> os.replace -> heartbeat.json` iterations with `0` errors. However, C#'s `LocalPythonOcrWorkerRunner.CheckStorageBounds` scans `writableRoot` every `1s` using `Directory.EnumerateFiles(writableRoot, "*", SearchOption.AllDirectories)`, which covers `runs/<attempt>/cache/{tmp,hf-home,hf-modules,torch-home,triton-cache,inductor-cache,cuda-cache,...}` and maps to `EnumerationOptions { RecurseSubdirectories = true, IgnoreInaccessible = false, AttributesToSkip = 0 }`. Under concurrent transient subdirectory creation/deletion inside `runs/attempt-1/cache/tmp`, `CheckStorageBounds` threw an unhandled **`System.UnauthorizedAccessException`** (NTFS `STATUS_DELETE_PENDING` / disappearing directory during enumeration, not caught by inner `catch (IOException)`) after **`85` iterations** (`Probe P3`, [stage1-verification-summary.json](stage1-verification-summary.json)), and `AttributesToSkip = 0` does not skip reparse points inside `writableRoot`.
  2. *Missing child termination in `finally` (`LocalPythonOcrWorkerRunner.cs` lines `239`–`247`)*: `finally` calls `jobProcess.TerminateAllInJob(1)` only when `abortCode is not null || cancellationToken.IsCancellationRequested`. When any exception escapes the `while (true)` supervision loop while the child is running (e.g., `CheckStorageBounds` throwing `UnauthorizedAccessException`/`DirectoryNotFoundException`, or `onHeartbeatAsync` throwing `NpgsqlException` during a PostgreSQL restart), `exitCode` and `abortCode` are `null`, so `TerminateAllInJob(1)` is **skipped** and `await Task.WhenAll(stdoutPump, stderrPump)` blocks waiting on open child stdio pipes while the child/grandchild continues running unsupervised (`using var jobProcess` at line `122` cannot dispose until `finally` finishes). Reproduced in `Probe P3` (`execute_task_blocked_waiting_on_pipe: true`, `child_still_alive_1200ms_after_loop_exception: true`).
  3. *Same-instance orphaned `running` wedge (`ExtractionAttemptCoordinator.cs` line `34`)*: Because `ReconcileAbandonedAttemptsAsync` unconditionally skips any row with `attempt.SupervisorInstanceId == supervisorInstanceId`, if finalization (`MarkAttemptFailedAsync` / `PublishCompletedResultAsync`) fails during a transient DB outage while `ELedgerCare.Api` stays up, subsequent supervisor ticks return `0` reconciled rows (`Probe P4`: `reconciled_by_same_live_coordinator_after_failure: 0`, `job_status_stuck_running: true`), wedging the job until the API process is restarted.
- **Required Resolution**:
  1. Harden `CheckStorageBounds` so transient file/subdirectory disappearance and NTFS pending-delete (`IOException` / `UnauthorizedAccessException`) during recursive traversal do not throw out of the guard, while skipping/rejecting reparse points inside `writableRoot` and preserving root existence/non-reparse checks, the `20 GiB` free-disk floor, and `4 GiB` subtree accounting.
  2. In `LocalPythonOcrWorkerRunner.ExecuteAttemptAsync`'s `finally` block, unconditionally call `jobProcess.TerminateAllInJob(1)` whenever `exitCode is null` (any non-normal loop exit) **before** awaiting `stdoutPump`/`stderrPump`.
  3. Track the coordinator's currently active in-flight attempt (or equivalent guard) so `ReconcileAbandonedAttemptsAsync` skips `attempt.SupervisorInstanceId == supervisorInstanceId` only while that attempt is actively executing, allowing same-process recovery of any orphaned `running` row once its launcher and worker `(pid, create_filetime)` identities are confirmed gone.

### `F2-S1-03` (Blocking — `F2-06`): Unsanitized `0x00` NUL bytes and UTF-16 surrogate-pair splits in `diagnostic_raw_output_utf8` / `failure_detail` abort `ExtractionStore.MarkAttemptFailedAsync`

- **Source Pins**:
  - [WorkerEnvelopeValidator.cs](../../../../../src/ELedgerCare.Application/Extraction/WorkerEnvelopeValidator.cs) lines `341`–`350`
  - [ExecutionAttempt.cs](../../../../../src/ELedgerCare.Domain/Processing/ExecutionAttempt.cs) lines `200`–`205`, `234`–`235`
  - [ExtractionStore.cs](../../../../../src/ELedgerCare.Infrastructure/Persistence/ExtractionStore.cs) lines `568`–`575`, `594`–`596`
- **Mechanism & Empirical Reproduction**:
  `WorkerEnvelopeValidator.TryExtractPreview` decodes rejected raw output bytes (`output_cap_exceeded`, `worker_output_digest_mismatch`, `model_output_truncated`, `page_count_mismatch`, or partial output on supervisor abort) with `Encoding.UTF8.GetString(slice)`, and `MarkAttemptFailedAsync` truncates C# UTF-16 strings via `value[..65536]` before binding `NpgsqlDbType.Text`. Against real PostgreSQL `18.7` (`127.0.0.1:55435`), `Probe P4` reproduced:
  - `0x00` NUL byte in `diagnostic_raw_output_utf8` -> `PostgresException` SQLSTATE **`22021`** (`invalid byte sequence for encoding "UTF8": 0x00`);
  - UTF-16 surrogate pair split across index `65,535` / `65,536` -> **`System.Text.EncoderFallbackException`** in Npgsql parameter encoding.
  Either exception aborts `MarkAttemptFailedAsync` instead of recording the failed attempt honestly.
- **Required Resolution**:
  Sanitize bounded diagnostic text (`diagnostic_raw_output_utf8` and `failure_detail`) prior to PostgreSQL `text` persistence by replacing `\0` (`U+0000`) with `\uFFFD` and avoiding UTF-16 surrogate-pair splits at truncation boundaries (`extraction_results.raw_output_bytes` is `bytea` and remains exact/unmodified for accepted results).
