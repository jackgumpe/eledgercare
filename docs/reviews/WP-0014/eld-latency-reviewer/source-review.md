# What the 53.374-second clock covers

The saved worker timer supports the reported 54-second scale. It measured 26.808 s in synchronized `infer_multi`, 12.261 s loading the tokenizer and model, and 0.182 s rendering. The remaining **14.123 s** is a subtraction. The original envelope covered one page, 279 prompt positions and 61 returned tokens. It omitted native time to first token. The 8,000-token cap is an upper bound. The generation loop terminated at the stop token. A report of decoder speed based on 61 divided by 26.808 would include image preprocessing and first-token work. [Filtered original and historical measurements](historical-timings.json)

The total starts inside the Python worker and stops after validating the result and writing the raw output. The measurements omit process launch, envelope publication, persistence, and browser observation. Render and model-load timings start after preflight. Preflight checks worker identity, installed packages, GPU, storage, model bytes and static source safety. It rehashes 18 model objects totaling 6,699,195,181 bytes plus the separate notice. `from transformers import AutoModel, AutoTokenizer` precedes the load timer as well. These activities have a place in the residual, but the original does not time each of them. Product worker loads one model per attempt and gives each attempt fresh Hugging Face and CUDA cache directories. ## Native single-request work

With cropping disabled, a 1024 × 1024 global page view costs 273 visual placeholder positions, with six additional positions for the one-page prompt and control tokens. The image size and positional budget apply even to a nearly blank page. The time to the first token includes vision encoding, decoder prefill and first-token selection. Upstream starts that clock after image preparation, device transfers and DASH setup. After this point the native loop executes one model step at a time, with a host-visible greedy token decision each step. [Pinned native generation](https://huggingface.co/baidu/Unlimited-OCR-2/blob/0480966938291445591f69f08a13b041c073a96a/modeling_unlimitedocr.py)

The product explicitly accepts the `triton_import_failed_dense_fallback` label. In six earlier Q0 one-page calls, 12 dense fallback calls occurred during prefill. The 1,122 subsequent decoder forwards called a separate FP32 DASH attention function 13,464 times. That function casts the keys and values to FP32 and applies a mask in the reference implementation. The single-device mixture-of-experts code also copies the per-expert counts to the CPU and dispatches expert calls through Python. The pinned config gives 11 mixture-of-experts layers and six routed experts per token. These observations motivate testing optimized serving kernels, but do not apportion seconds to individual operators. [Decoder](https://huggingface.co/baidu/Unlimited-OCR-2/blob/0480966938291445591f69f08a13b041c073a96a/modeling_deepseekv2.py) · [Experts](https://huggingface.co/baidu/Unlimited-OCR-2/blob/0480966938291445591f69f08a13b041c073a96a/_sparse_base_impl.py) · [Config](../../../../research/astra/sources/hf-config.json.txt) · [Product observer](../../../../workers/local_ocr/local_ocr/observer.py)

On the same RTX 5070 Ti, two previous Q0 sessions used the same synthetic F01 page and produced 1,122 tokens each time. Native first-token times were 19.262 and 18.450 s on their first calls, then 0.367–0.516 s on four resident repeats. The initial calls had already loaded the model. The six post-first-token rates were 9.01–9.42 decode steps/s including the final EOS decision. The richer Q0 observer accrued 0.275–0.328 s of callback self-time per call. This excludes interpreter dispatch, and does not measure the product observer's total overhead. The original document's native breakdown and the cause of the first-forward gap within CUDA/PyTorch remain unresolved by these historical observations. [Recalculation](historical_timings.py) · [Six measurements](historical-timings.json)

CUDA can defer module loading until first use. NVIDIA documents lazy loading as the Windows default since CUDA 12.3. The attempt-local `CUDA_CACHE_PATH` also gives a new JIT-cache directory to each worker. The actual kernels loaded, compiler activity and time spent in these mechanisms were not profiled. Reusing a model after a representative warmup directly tests the combined first-use effect; choosing eager loading alone could move work to startup. ## Published v2 numbers

Baidu’s native Transformers example loads the model once on an A800-80GB with Python 3.10. For serving, the authors provide a customized SGLang wheel with CUDA graph capture, batching, and custom generation controls. A relevant latency comparison would hold the model revision, base image mode, page bytes, single-job concurrency, stop/guard behavior, generated lengths and correctness fixed. The example client defaults to tiled Gundam mode. The same setting as the product is explicitly `crop_mode=False`. A server startup cost belongs in first-user latency whenever the service starts on demand. [Baidu’s v2 recipe](https://github.com/baidu/Unlimited-OCR/tree/64e6f066023b305ab03860603a9cf358a8b70148#inference)

The v2 paper’s 7.0× and 5.6× results compare attention strategies at hundred-page scale. Figure 6(b) uses batches of three, Gundam mode and fixed generation of 1,024 tokens per page. Table 4 quotes 1,315 versus 360 tokens/s in aggregate at batch size 16 on MarathonDocBench. Its 1.77 and 47 GB KV peaks are measured separately at batch size one. Section 4.2 names H800 GPUs for training. These figures provide no cold-upload latency prediction for one short base-mode page on Windows and a 16 GB RTX 5070 Ti. [Paper, methods and experiments](https://arxiv.org/html/2610.39308v2#S5.SS3)
