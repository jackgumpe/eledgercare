# WP-0011 public interface (no fresh examples)

This file is schema-only. Fresh identifying payload remains sealed with the custodian until independent protocol/source and corpus acceptance plus root unseal. No author inspection of private generation code, ideal witnesses, labels, values, headers, boxes, PDFs or renders occurs during preparation.

Explicit `quantity_unit` metadata on expected fields/cells, when supplied, must be a nonempty string. Its presence and value are paired semantics; an omitted key is not equivalent to a supplied value. Expected absences require `expected_state=absent_blank` and `label_printed` exactly equal to the condition's annotation. Absence state is part of the semantic signature; label wording remains condition-specific.

Exactly three families `WP11-F01`, `WP11-F02`, `WP11-F03`; each has four one-page fixture IDs `<family>-control-v0`, `-layout-v0`, `-vocabulary-v0`, `-degraded-v0`. Order is family-major, then control/layout/vocabulary/degraded. Independent sentinel is fixed before outputs as `WP11-F03-degraded-v0`. Future public artifacts preserve `corpus/r1/{pdfs,expected,reference,annotations}/<fixture_id>.<pdf|json>` under `evaluation/coverage_v1/`.

Expected JSON retains B0's object: fixture_id/family_id/split/variant_kind strings, page_count integer, expected_fields/expected_tables/expected_absences/page_sentinels/expected_adjacent_page_pairs/cross_page_links arrays. `split=diagnostic_eval`, `variant_kind=condition`; page_count1, no cross-page links/adjacency. Each expected field includes canonical field_id, page_number1, label_printed, printed_text, normalized_value and value_type strings. Expected tables retain table_id, column_ids and rows, with stable row_id, page_number and cells keyed by canonical column. Cell printed_text/normalized_value/value_type are strings. Absence slots are explicit field_id/page_number pairs, distinct from filled fields. References retain `pages:list[str]` of length1 and `coverage:object`; optional runs/operator metadata stays reference-side.

Annotations use `schema=eld-coverage-annotations/1`, fixture_id/family_id/condition/control_fixture_id strings, page_count1, and:

- `fields`: complete unique `{field_id:str,page_number:int,label_printed:str,label_bbox_pt:list[number,number,number,number],value_bbox_pt:list[number,number,number,number]}` entries.
- `tables`: complete unique `{table_id:str,page_number:int,headers:list[str],column_ids:list[str],row_key_column:str,header_bbox_pt:list[number,number,number,number]}` entries. Column order is printed order; row_key_column is a canonical column with unique nonempty printed row keys within the expected table. Expected row/cell identities stay stable across conditions.
- `absences`: complete unique `{field_id:str,page_number:int,label_printed:str,label_bbox_pt:list[number,number,number,number]}` entries.
- `ideal_native:str`: canonical perfect-reading native-markup witness of the condition's actual printed arrangement, including correctly normalized native coordinates, decoded visible text, unit-span table structure as actually laid out, and explicit empty absence slots. This is private ground truth, not an inference output.

Boxes are finite nonnegative PDF-point `[left,bottom,right,top]` with positive extent. Labels/headers/boxes are condition-specific. Values, canonical slots/row IDs/types/absence meanings stay paired. Degraded reference text, annotations and ideal witness equal its own control; only fixed scan quality changes. Vocabulary keeps geometry/font/wrapping fixed while changing only labels/header wording. Layout keeps wording/value multiplicity/style fixed while changing arrangement. Independent admission must verify these restrictions from visible renders/source, because schema checks alone cannot prove one-factor visual isolation.

`contract.validate` checks schema/identity/completeness; `validate_family` checks all four conditions' semantic identity and degraded-control metadata equality. `support_control` requires exact frozen label-to-field and header/column support, parses the ideal witness through both unchanged B0 and mapping-v1, and requires full printed field/cell/row, explicit absence and page-count credit with no surplus field/row/cell candidates. A v1-only adjacent-value witness is not accepted as B0 control support. This proves ideal support, not actual OCR success. Independent admission must establish the witness faithfully describes the rendered control. No witness/annotation/expected value is supplied to actual predictions.

CPU entry point after exact helper binding: `python -I -B qualification/coverage_v1/cli.py support-control --expected <authorized expected> --reference <authorized reference> --annotations <authorized annotations> --output <new owned output>`. The custodian/reviewer may use it on their authorized sealed data; the mapping author uses only independent tiny test data and exposed historical data. Future execute/worker/score-run are separate exact-release entry points and remain unreleased during CPU preparation.
