**Loader risk:** model entrypoint has try/except imports of `sparse_gather_triton` and `sparse_gather_e2e_triton`; those modules themselves import triton unconditionally. Transformers' AST import checker skips try blocks, but its *remote-ID* branch recursively calls `get_cached_module_file` for relative files and runs `check_imports` on each. It can therefore demand triton on an optional leaf before the model's runtime fallback gets a chance. This is a source-derived predicted failure, not an observed ImportError.

**Proposed path:** prepare the complete hash-verified unmodified model in the task's explicit local directory, then pass that directory to AutoTokenizer/AutoModel with `trust_remote_code=True`, `local_files_only=True` and an isolated HF_MODULES_CACHE. In this pinned loader's *local-directory* branch, direct relative sources are copied without recursive third-party checks. The model explicitly names its second-level sources at the entrypoint for this reason. Verify importability of the local class without loading weights or allocating CUDA in the separately authorized import stage; if that still fails, stop and report instead of adding Triton or editing source. Offline flags/cache paths must be set before any HF import. This preserves the unmodified source and avoids remote-ID recursion rather than pretending optional source is unnecessary.

The model catches Exception around optional fused imports and provides native dense/SDPA prefill and fp32 decode paths; `_uocr_generate` uses a growing DynamicCache with ring/sliding disabled. Source fallback existence does not establish safe memory/latency or successful full import. Capture native call-path telemetry externally (e.g. a reviewed profiler/event observer) without modifying source, replacing kernels or enabling training/debug behavior that changes computation.
