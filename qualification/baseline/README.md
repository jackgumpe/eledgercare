## Data boundaries and executable rules

`native.py` accepts raw model text and frozen **dev label/header rules only**. It cannot read corpus truth. `score.py` compares the completed prediction object with expected records. `corpus.py` is the separate scoring-reference side: it rejects holdout content before opening any source/expected/PDF unless the released test stage explicitly permits it. `prepare.py` reads only admitted dev expected/source records; its output contains labels/header structures, never expected field values or fixture-specific extraction lookups. Public manifest IDs/hashes/page counts for all 26 inputs are in `protocol.json`. No upstream unsafe postprocessor/eval is invoked.

Native parser: `<PAGE>` in encounter order, `<BLOCK>kind[0..1000 coordinates]<FORK>body` with optional `<LEVELn>`; page and block order is preserved. No coordinate-based page/block reordering. HTML tables use stdlib HTMLParser with text entity decoding and only table/section/row/cell/br grammar. One physical cell per td/th; colspan is retained, rowspan other than 1 is unsupported. Unknown tags/attributes, broken spans/header/coordinates or unclosed structures produce parse errors, retain raw diagnostics and invalidate exact credit. Caps: 16 MiB raw, 10,000 blocks, 20,000 cells. Raw input remains the authoritative evidence even where recovery is incomplete.

Frozen field mapping: dev labels, longest label first, case-sensitive NFC, optional structural colon; inline value ends at the next recognized label. Separate label blocks select the nearest non-label/non-table/non-footer block to their right with top-y difference <=5 native units, else a directly lower block within 25 y units and 12 x units. This is generic structural alignment, not expected-value search. Table-shaped label/value pairs can use equal-width next rows. Long/multiline address or unfamiliar-layout mappings may fail; no expected coordinates, known strings, inferred total or fixture template ID repairs them. All candidate occurrences survive. Unknown colon labels and all otherwise unmapped content are retained.

Tables: only exact dev header sequences identify a table and its column IDs. Repeated exact headers start another segment and are not data rows. Header OCR errors are **not repaired**: their table content remains unmapped and every expected cell stays in its denominator. Known table rows align by page, table ID and encounter-order ordinal; no ground-truth value-based row matching. Extra rows/cells and duplicate field candidates are counted. This conservative rule may penalize all later rows after an omission; it is explicit and frozen, not a fuzzy alignment claim.

Exact field/cell scoring compares `printed_text` with predicted strings after **NFC, CRLF/CR to LF and outer strip only**. Digits, identifier leading zeros, currency symbols/signs/grouping, punctuation, internal whitespace and letter case are untouched. `normalized_value` is retained in field diagnostics; semantic currency/boolean/rate normalization is deliberately not claimed because it exceeds this contract's permitted normalization. Correctness numerators require a completed, parse-valid document. Partial failed outputs retain observed comparisons but receive zero exact credit. Missing/unmapped expected fields, rows, cells, absences and links retain denominators. Expected absence is verified only with an explicit mapped empty candidate; no candidate is unknown, not proof of absence. A nonempty candidate is an absence violation.

Unmatched fields/rows/cells are schema-relative excess candidates, **not automatically factual hallucinations**: the schema does not annotate all legitimate repeated furniture. Unknown prose and table rows/cells remain in `unmapped_content`; this implementation cannot comprehensively judge invented semantics. Text insertions and duplicate tokens provide an additional lexical signal. No LLM judge is used.

Page metrics count native pages, exact PG-ANCHOR values at each expected page, and adjacent sentinel pairs. Cross-page rules support repeated document/contract IDs from mapped label values, table continuation first/last row IDs, and final-page-only summary location. Unseen link types are explicitly unsupported/incorrect and remain in the link denominator. No expected value is used to locate a prediction.

## Document-text reference and coverage

The corpus expected schema has no full-document transcript. Reference construction is explicit and separate from prediction: verify the family's admitted v0-clean PDF hash, read only this corpus writer's bounded Flate content streams and escaped ASCII `Tm (...) Tj` grammar, and include **every** text operator, including titles, footers, repeated header labels/values, explanatory text, row/cell values and summary furniture. Text order is page order, descending exact baseline y, ascending x, original operator ordinal for ties. This is a spatial row-major reference, not an assertion of uniquely correct human reading order. The model's native block order remains unchanged, so column/row ordering differences contribute to its text error count.

Raster and skew variants use that verified clean-parent text reference; no embedded text shortcut enters model input. For a hybrid variant, its verified source-record `hybrid_control` contributes both label and printed body on the declared target page, ordered at top-of-box minus 10/24 points and x-left. This includes the raster-only addendum absent from vector text. These two declared logical lines do not pretend to recover individual raster glyph positions. Any unsupported PDF/text operator, page-count mismatch or missing hybrid binding fails reference construction; coverage must be reported rather than silently omitted. The reference is complete for this admitted writer/declarative-addendum contract, not a universal PDF transcript extractor.

Tokenization is Python Unicode whitespace splitting after NFC/line-ending/outer normalization. Punctuation remains attached. Deterministic `SequenceMatcher(autojunk=False)` aligns token sequences; replacement contributes min(lengths) substitutions and remaining tokens deletions/insertions. Error rate=(S+D+I)/reference tokens and may exceed 1. It is **not minimum-Levenshtein WER**. Above 12,000 tokens on either side, text alignment is explicitly unsupported with both token counts retained; exact fields/cells and document failures still count. Per-document numerators/denominators precede equal document means within family, then equal family means within split. Dev and test never pool; variant counts/completions are separate, and variants are correlated observations. Zero-denominator metrics use null with coverage counts, never fabricated perfect scores.

Reviewer execution uses its preselected subset. Guards preserve Q0 load/per-call/stall/raw/log limits and 6h cap; owned-directory usage and C: floor are polled. First failure stops the session; all remaining planned documents remain `not_run_after_failure`, never disappear or get retried. Model/native raw output, token IDs, finish/page counts, timings, rendered RGB hashes, path/memory telemetry and WDDM observations are retained.

Windows kill-on-job-close ownership requires the actual worker to join the supervisor's named job before runtime imports, including a venv redirector child. Closing/crashing the supervisor terminates that owned worker; no unrelated processes are inspected for termination. On failure, parent retains available raw records and marks the active call failed. No same-session retries or substitutions. One call/document gives descriptive quality/latency observations, not paired improvement evidence or population accuracy. CUDA run paths are unexecuted in this CPU packet and need independent review plus release.
