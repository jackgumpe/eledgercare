## Data boundaries and executable rules

`native.py` accepts raw model text and frozen **dev label/header rules only**. It cannot read corpus truth. `score.py` compares the completed prediction object with expected records. `corpus.py` is the separate scoring-reference side: it rejects holdout content before opening any source/expected/PDF unless the released test stage explicitly permits it. `prepare.py` reads only admitted dev expected/source records; its output contains labels/header structures, never expected field values or fixture-specific extraction lookups. Public manifest IDs/hashes/page counts for all 26 inputs are in `protocol.json`. No upstream unsafe postprocessor/eval is invoked.

Native parser: `<PAGE>` in encounter order, `<BLOCK>kind[0..1000 coordinates]<FORK>body` with optional `<LEVELn>`; page and block order is preserved. No coordinate-based page/block reordering. HTML tables use stdlib HTMLParser with text entity decoding and only table/section/row/cell/br grammar. One physical cell per td/th; colspan is retained, rowspan other than 1 is unsupported. Unknown tags/attributes, broken spans/header/coordinates or unclosed structures produce parse errors, retain raw diagnostics and invalidate exact credit. Caps: 16 MiB raw, 10,000 blocks, 20,000 cells and 100,000 HTML events per table. Raw input remains the authoritative evidence even where recovery is incomplete.

Frozen field mapping: dev labels, longest label first, case-sensitive NFC, optional structural colon; inline value ends at the next recognized label. Separate label blocks select the nearest non-label/non-table/non-footer block to their right with top-y difference <=5 native units, else a directly lower block within 25 y units and 12 x units. This is generic structural alignment, not expected-value search. Table-shaped label/value pairs can use equal-width next rows. Long/multiline address or unfamiliar-layout mappings may fail; no expected coordinates, known strings, inferred total or fixture template ID repairs them. All candidate occurrences survive. Unknown colon labels and all otherwise unmapped content are retained.

Tables: only exact dev header sequences identify a table and its column IDs. Repeated exact headers start another segment and are not data rows. Header OCR errors are **not repaired**: their table content remains unmapped and every expected cell stays in its denominator. Known table rows align by page, table ID and encounter-order ordinal; no ground-truth value-based row matching. Every non-header physical row after a recognized header occupies its native ordinal. Short nonspanning rows map their available cells and retain missing cells; spanning rows retain physical values/cells but map no column values. Both carry explicit unmapped diagnostics. Extra rows/cells count physical cells (not invented colspan-expanded cells); unmapped physical row/cell counts remain separate. Unknown tables retain every row. Extra rows/cells and duplicate field candidates are counted. Per-document `mapping_coverage` reports candidate counts versus expected counts, missing/unmapped row counts, reasons and unclassified content. Exact-cell mismatches combine mapping and recognition failures; they are not characterized as measured character-reading errors. Raw lexical text errors remain separate. This conservative rule may penalize all later rows after an omission; it is explicit and frozen, not a fuzzy alignment claim.

Exact field/cell scoring compares `printed_text` with predicted strings after **NFC, CRLF/CR to LF and outer strip only**. Digits, identifier leading zeros, currency symbols/signs/grouping, punctuation, internal whitespace and letter case are untouched. `normalized_value` is compared separately by the strict typed metrics specified below, following the coordinator's pre-test scope clarification; the printed metric definition is unchanged. Correctness numerators require a completed, parse-valid document. Partial failed outputs retain observed comparisons but receive zero exact credit. Missing/unmapped expected fields, rows, cells, absences and links retain denominators. Expected absence is verified only with an explicit mapped empty candidate; no candidate is unknown, not proof of absence. A nonempty candidate is an absence violation. Only the first occurrence consumes the absence slot; every surplus occurrence, including empty ones, also counts as an unmatched field candidate and an absence surplus.

Unmatched fields/rows/cells are schema-relative excess candidates, **not automatically factual hallucinations**: the schema does not annotate all legitimate repeated furniture. Unknown prose and table rows/cells remain in `unmapped_content`; this implementation cannot comprehensively judge invented semantics. Text insertions and duplicate tokens provide an additional lexical signal. No LLM judge is used.

Page metrics count native pages, exact PG-ANCHOR values at each expected page, and adjacent sentinel pairs. Cross-page rules support repeated document/contract IDs from mapped label values, table continuation first/last row IDs, and final-page-only summary location. Unseen link types are explicitly unsupported/incorrect and remain in the link denominator. No expected value is used to locate a prediction.

## Strict typed normalized-value metrics (/007 clarification)

`normalized_fields` and `normalized_cells` use exactly the corresponding printed expected-item denominators and the same completion/parse eligibility. Conversion in `typed_values.convert(raw, value_type, slot)` accepts no expected answer. It uses only raw candidate text, the declared schema type and the explicit `qty_unit` slot; expected `normalized_value` is compared afterward as a canonical string. Nothing feeds back into extraction. Details retain raw text, type, conversion status, canonical value, expected canonical target, observed comparison and credited comparison. Missing/unparsed/unsupported values, unsupported target shapes and failed documents remain counted, with reason counts. Family/variant summaries report both metric sets. Excess/duplicates/absence/mapping and raw lexical errors are independent of typed credit.

After the same NFC/line-ending/outer-strip rule, frozen lexical grammar is:

- `identifier` and `text`: exact string, including leading zeros, case, punctuation, internal spaces and line breaks. Addresses are not joined or reordered.
- `date_iso`: ASCII `YYYY-MM-DD` plus a valid Gregorian date, unchanged.
- `boolean_mark`: exactly `[X]` -> `true`, `[ ]` -> `false`; no inferred truth words or lowercase/cross substitutions.
- `decimal_2`: optional leading ASCII minus, integer `0` or a nonzero leading digit followed by at most 23 digits, optional dot plus 1–6 ASCII fractional digits. No grouping, exponent, plus, parentheses, digit repair or unit guessing.
- `currency_usd`: same numeric grammar, optionally `$` immediately after the optional minus; alternatively valid comma grouping (1–3 nonzero-leading initial digits, then 1–7 groups of exactly three digits). No other currency/sign placement is accepted.
- `rate_percent`: decimal grammar followed by mandatory `%`, divided by exactly 100. Bare fractional rates are ambiguous and rejected; negative rates are retained as signed values, never repaired. No inferred range or total.
- `decimal_2` in `qty_unit` requires exactly one space and a dev-observed uppercase unit `BX|EA|HR|KT|PR`. The unit is retained and validated; normalized quantity compares the number only because the schema target contains only that number. A wrong but supported unit can therefore receive normalized numeric credit while printed equality fails. Other decimal slots reject suffixes.

USD/decimal quantities must represent an exact two-place value, percentages an exact four-place fraction. Decimal precision 40, at most 128 characters for typed scalars, at most six fractional digits; quantization is accepted only if it does not change value. Extra fractional zeroes are permitted; sub-cent/sub-rate precision, negative zero, nonfinite values, Unicode numeric glyphs and unknown types/structures fail explicitly. Canonical output has exactly two/four decimal places; booleans use lowercase strings. No rounding-based credit, money inference or identifier-zero stripping occurs. Empty text remains a string, not a guessed absence.

Rules were frozen using only the 13 dev expected records and admitted schema semantics. CPU checks include all dev printed values plus synthetic formatting/wrong-sign/wrong-digit/leading-zero/invalid-grouping/unsupported-unit/failed-document cases. The dev grammar coverage audit is reference-side validation, not model accuracy. Retrospective F01/F07 scores reuse the same retained Q0 raw bytes and remain distinct from future B0 measured results.

The closed table grammar requires exactly one `table` root, properly nested optional `thead|tbody|tfoot`, `tr`, and `td|th`; `br`/`br/` is allowed only in a cell. Every tag except cells rejects all attributes; cells permit only unique, valued `colspan|rowspan` with ASCII positive integer syntax, colspan 1–100 and rowspan 1. Missing/mismatched closes, extra roots, self-closing structural tags, comments/declarations and unsupported tags fail. A malformed table retains its native body and per-page diagnostic; the document receives no exact credit, and subsequent documents still score.

## Document-text reference and coverage

The corpus expected schema has no full-document transcript. Reference construction is explicit and separate from prediction: verify the family's admitted v0-clean PDF hash, read only this corpus writer's bounded Flate content streams and escaped ASCII `Tm (...) Tj` grammar, and include **every** text operator, including titles, footers, repeated header labels/values, explanatory text, row/cell values and summary furniture. Text order is page order, descending exact baseline y, ascending x, original operator ordinal for ties. This is a spatial row-major reference, not an assertion of uniquely correct human reading order. The model's native block order remains unchanged, so column/row ordering differences contribute to its text error count.

Raster and skew variants use that verified clean-parent text reference; no embedded text shortcut enters model input. For a hybrid variant, its verified source-record `hybrid_control` contributes both label and printed body on the declared target page, ordered at top-of-box minus 10/24 points and x-left. This includes the raster-only addendum absent from vector text. These two declared logical lines do not pretend to recover individual raster glyph positions. Any unsupported PDF/text operator, page-count mismatch or missing hybrid binding fails reference construction; coverage must be reported rather than silently omitted. The reference is complete for this admitted writer/declarative-addendum contract, not a universal PDF transcript extractor.

Tokenization is Python Unicode whitespace splitting after NFC/line-ending/outer normalization. Punctuation remains attached. Deterministic `SequenceMatcher(autojunk=False)` aligns token sequences; replacement contributes min(lengths) substitutions and remaining tokens deletions/insertions. Error rate=(S+D+I)/reference tokens and may exceed 1. It is **not minimum-Levenshtein WER**. Above 12,000 tokens on either side, text alignment is explicitly unsupported with both token counts retained; exact fields/cells and document failures still count. Per-document numerators/denominators precede equal document means within family, then equal family means within split. Dev and test never pool; variant counts/completions and family-macro metric means are separate, and variants are correlated observations. Zero-denominator metrics use null with coverage counts, never fabricated perfect scores.
