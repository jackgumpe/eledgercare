## Architecture facts and applicability

The refreshed [config](sources/hf-config.json.txt) names `UnlimitedOCRForCausalLM` with custom AutoConfig/AutoModel mappings. It specifies a 12-layer, 1280-hidden-size decoder, 10 attention and KV heads, 64 routed experts with 6 selected per token plus 2 shared experts, bfloat16, and nominal maximum positions 131072. The vision configuration names SAM ViT-B and CLIP-L components; [modeling_unlimitedocr](sources/hf-modeling_unlimitedocr.py.txt), constructor around lines 629–640, constructs both and a linear 2048-to-1280 projector. This is a multimodal generative model, not a PDF text parser or maintenance-field schema.

The sparse configuration selects DASH-stage sparse attention, block size 32, local blocks 4, selected-block settings, page/image token IDs, and page-aware rotary position settings. That is source configuration evidence; the effective inference path also changes settings at runtime. Do not equate a configured sparse read set with bounded allocated memory.

The native `infer_multi` wrapper defaults to uncropped global views; `infer` uses dynamic tiles by default for one image, with 1024 global size, 640 tile size and up to 16 crops. Mixing those entry points silently changes image treatment. Pin the wrapper and explicit crop mode in any comparison. Source anchors: `_uocr_build_inputs`, `infer`, `infer_multi` in [modeling_unlimitedocr](sources/hf-modeling_unlimitedocr.py.txt), approximately lines 531, 1039 and 1110.

A significant implementation limit appears in native `_uocr_generate`: it constructs `DynamicCache`, disables `_ring_window` and `sliding_window`, and stops at token/context limits. In [modeling_deepseekv2](sources/hf-modeling_deepseekv2.py.txt), `_dash_decode_forward` appends KV and index keys; `_decode_attend` builds sequence-sized masks and casts full K/V to float before dense matmuls. Therefore the native reference code has sequence-length-dependent storage/work despite sparse masking. This is a static inference from the inspected code, not a measured memory curve or proof of the custom SGLang implementation. The paper abstract's broad constant-cost claims cannot be transferred to every released path.

Triton is imported by the fused gather kernel text. `_forward_triton` catches import errors and returns None; alternate paths exist. Absence of an import error would not establish that the intended fused path ran. Qualification must capture which kernel/path actually executed. The full custom SGLang wheel internals and complete source-to-wheel correspondence remain uninspected.

The raw output is structured layout tokens, not ready-made Markdown or application fields. Upstream [postprocessing documentation](sources/github-utils-README.md.txt) describes page splitting, cross-page table/block merges and cleanup. Preserve raw outputs and freeze postprocessing separately; page-marker counts alone cannot prove content completeness. The actual postprocessor implementation has not been audited in this packet.
