## Proposed ranking and finite decision rules

Q0 is separate engineering qualification, not a fourth improvement: choose an owned OS/runtime/storage path, pin the exact CUDA/build/tokenizer/renderer/parser dependencies, use safe output handling, and qualify one admitted development page plus one ordered three-page document. Default to the simplest qualified native path for this shortlist; if it fails, report that blocker without inventing a score. No model/GPU execution is released now.

For all future A/B comparisons: same model/source pin above, one native wrapper, explicit crop mode, identical rendered input bytes except the declared image treatment, greedy generation, fixed page/total-token budgets and ngram guards, fixed raw parser and item normalization. Freeze budgets without held-out answers and count omissions, extras, truncation, page order and cross-page links, not just PAGE markers. Keep per-document results, then equal-weight family means. One excluded warmup and three interleaved warm repeats per condition suffice for this diagnostic set; no significance claim or provider ranking. Thresholds below are proposed decision rules, not measured benefits.

| Rank / lineage | Single treatment and minimum future comparison | Denominators and rejection rule |
| --- | --- | --- |
| 1 — explicit tiling (Astra H1 / Carbon H-C2) | Same native `infer_multi` wrapper with crop_mode False vs True, base_size=1024, image_size=640, max_crops=16, save_results=False. Eight clean originals; F05/F06 dense invoices and F08 multipage holdout are the predeclared quality subset. All other flags unchanged. | Exact table cells / all expected cells per document; equal-weight family delta. Require >=5 percentage-point mean gain on F05/F06/F08 with no individual regression, no new identifier/amount/page/link failure, no truncation/OOM, and median document latency ratio <=2.0. Otherwise reject promotion, including zero gain even if fast. Record total visual/output tokens and qualified memory envelope; no automatic sequential-page substitution. |
| 2 — conditional deskew (Astra H2 / Carbon H-C3) | On the unrotated raster and one rotated raster per family, freeze base crop=False in both arms. Use Astra's finite projection-variance search [-5,+5] by 0.1 degree on a grayscale/Otsu diagnostic mask, fixed tie break, trigger abs(angle)>=1 degree and >=10% score improvement; rotate RGB once with fixed bilinear interpolation/expanded white canvas. Carbon may replace this algorithm only explicitly before held-out use, not mix projection and Hough opportunistically. | Exact fields / expected fields and exact cells / expected cells separately, equal-weight four holdout families. Require >=5-point field gain on rotated holdouts, no cell regression/new amount/identifier/link/page error, and end-to-end median ratio <=1.10. Any clean false trigger or non-identical no-op bytes rejects. Record angle error only after prediction freeze; no oracle transform metadata to estimator. OOM/truncation remains failure. |
| 3 — conservative text-layer routing (Carbon H-C1, newly considered by Astra) | First CPU feasibility only: vector originals, image-only variants and at least two linked hybrid negative controls. Counterexample: meaningful raster note or stamp below 15% area while ordinary text clears the character threshold. Start by abstaining on any page image or uncertain visible-text mapping; no claim that a permissive logo exception is safe. Freeze one gate + coordinate extractor as one declared pipeline treatment, then compare against unconditional qualified OCR with same downstream schema. | Misrouted scan/hybrid pages / every designated scan/hybrid page; expected fields/cells per document and extra predictions. Any bypass of a designated non-digital page, new omission/false field, or negative per-document paired correctness delta rejects. After CPU feasibility passes, require >=50% median end-to-end latency reduction on routed clean holdouts, including gate/extraction/normalization. No asserted <100 ms or 95% gain. If empty routed set or controls missing, no positive conclusion. |

For rank 3, CPU feasibility is not a paired OCR result and can fail the candidate before any GPU allocation. Keep latency targets and acceptable memory bounds predeclared in a future execution packet, with actual platform measurements. None of these proposals makes F1 depend on OCR or creates a production ExtractionResult contract.
