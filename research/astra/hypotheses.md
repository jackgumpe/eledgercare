# Three falsifiable hypotheses — proposed only

Author: eld-rd-astra, WP-0004 / 001. These are upstream-only proposals. None has run; no benefit, baseline score, local hardware suitability, accepted backlog, or production integration is claimed. All source pins and qualification gaps are in [assessment.md](assessment.md). Runtime qualification is Q0, a prerequisite with a pass/fail receipt, not a fourth improvement hypothesis.

## Common comparison contract

Freeze model `baidu/Unlimited-OCR-2@0480966938291445591f69f08a13b041c073a96a`, custom source from that revision, full tokenizer revision, exact runtime dependencies, renderer, postprocessor and scoring revision before execution. Dependency versions not yet resolved must be filled during Q0 rather than guessed here. The reference Python recipe is a lead for Q0, not a working lock file. Each card uses one fixed engine within its A/B pair; native-vs-SGLang results must never be pooled as a single ablation.

Use the [eight-family split](corpus-proposal.md). Freeze output budgets without reading held-out answers: proposed native max_length 131072, max_new_tokens=min(8000 * page_count, remaining context budget), max_page_tokens 20000; same ordered page images, explicit prompts, greedy decoding, page guards, and ngram controls in both arms. These are prospective protocol values to qualify and freeze. An over-budget input is an explicit unsupported case, not silently shortened. Preserve exact raw output, finish reason, rendered input hashes, effective flags and kernel path logs. Native no-repeat ngram defaults differ from the SGLang client; do not call these equivalent.

Scoring uses expected fields and row cells fixed before inference. Trim outer whitespace, normalize Unicode NFC and line endings; do not repair digits, strip leading zeros from identifiers, infer missing totals, or use another LLM to judge correctness. Numeric currency comparisons use exact decimal minor units under a declared locale. Identifier/text fields require exact normalized matches. Unmapped/missing/incorrect fields count as failures. Additional invented fields/rows are counted separately. Keep a blinded manual adjudication path when the frozen raw-output parser cannot map a region; ambiguous scoring blocks a claim rather than silently dropping a case.

For every eligible attempted document, report exact fields / expected fields, exact table cells / expected table cells, omissions / expected items, extra rows, page-order errors / expected adjacent page pairs, completeness and execution outcome. A post-Q0 OOM, timeout or truncated output stays in the document denominator as a failed completion. Do not replace scores of a wholly unqualified runtime with zero. Summarize each family, then equal-weight family means; derived variants and repeated runs are not independent observations. No significance claims from this starter set.

Timing: fixed owned host/runtime/GPU state, one warmup excluded and three measured warm runs per A/B condition, interleaved in a predeclared AB/BA order, concurrency 1, synchronized GPU boundaries; record all wall times, renderer/preprocess/inference/postprocess stages, peak allocated/reserved GPU memory and process RSS. Report median per-document ratios and individual failures, with cold-load timing separate. If background GPU use cannot be controlled/recorded, mark timing inconclusive. No GPU use, installation or model download is released by these cards.

## H1 — explicit tiling recovers dense page content (rank 1)

- **Source/limitation:** native `_uocr_build_inputs` and `infer_multi` use a single padded 1024 global image per page by default; dynamic tiles are available. Small table text may lose useful resolution in a global view. This is a plausible mechanism, not an observed local error.
- **Single treatment:** set `crop_mode=True` instead of False in the SAME native `infer_multi` call for every document (including one-page documents). Keep base_size=1024, image_size=640 and max_crops=16 fixed. No renderer/DPI, crop-count tuning, prompt change or model change.
- **Vanilla baseline:** qualified native model at the shared pin, `infer_multi(crop_mode=False)`; all other effective settings and output limits as above. Explicit use of the same wrapper avoids the single-page auto-crop confound.
- **Controls/confounds:** same PDFs rendered with the frozen renderer at 300 DPI, identical raw parser and expected fields. More image tokens can shrink output budget; log prompt length and remaining budget and reject the comparison if truncation accounts for the apparent change. Sparse routing and tile seams may create duplicates. Runtime variation is controlled as above.
- **Prediction:** better exact cell/field recall on dense invoices, higher latency/memory; magnitude unmeasured. No prior promise of benefit on sparse work orders.
- **Metrics/rejection:** primary = equal-family mean exact table-cell rate for invoice families INV-01/02/03 and MP-02, denominator all predeclared expected table cells including omissions. Retain only if improvement is >=5 percentage points on held-out INV-03 and MP-02 combined by equal family weight, neither regresses, no new identifier/total error or incomplete document occurs anywhere, and median document latency ratio <=2.0. Otherwise reject for promotion on this corpus. A runtime/OOM failure is reported, not selectively omitted.
- **Smallest future execution:** tune nothing on held-out families; paired runs of 8 clean originals after Q0, then one frozen held-out evaluation. Qualification and development use only development families. If image-token limits prevent a fair budget on MP-02, declare that limitation and do not claim the threshold was met. No extra corpus or parameter sweep.
- **Resources/promotion:** one leased CUDA-capable GPU and isolated model/input/output storage; actual capacity requirement unknown, may exceed the observed host. A future bounded worker flag and regressions would be needed for product promotion; no model/kernel edits.

## H2 — conditional deskew improves mildly rotated raster pages (rank 2)

- **Source/limitation:** inspected `_uocr_build_inputs` pads/resizes and optionally tiles; it has no deskew step. The corpus can contain deliberately rotated raster variants. This supports testing sensitivity, not a claim about real scanned maintenance records.
- **Single treatment:** add one deterministic conditional deskew stage before unchanged native inference. Proposed algorithm: grayscale Otsu mask; search rotations from -5.0 to +5.0 degrees at 0.1-degree steps, choose maximum horizontal projection-variance score with smallest absolute angle then signed-angle tie break; rotate only when absolute estimated angle >=1.0 degree and score improvement >=10% over zero. Use fixed white expanded canvas and one bilinear resampling. Freeze exact library/version and tie/rounding implementation during development. No denoising, sharpening, thresholded image output, or oracle rotation metadata passed to the algorithm.
- **Vanilla baseline:** qualified native `infer_multi(crop_mode=False)` on uncorrected input rasters, same model/config/runtime and budgets as H1's baseline. Treatment consumes the identical raster bytes before its optional correction.
- **Controls/confounds:** paired clean raster and +3-degree raster variants for each family, fixed font/rendering and page dimensions. Save estimated/applied angles and resulting dimensions. Resampling/canvas changes are part of this treatment. Table rules, vertical text and sparse pages may fool the estimator; include them in the denominator. Do not tune angles on held-out expected fields.
- **Prediction:** higher exact field/cell recall on rotated variants; small CPU preprocessing cost. Clean-page unnecessary transformations should be rare. No prediction for handwriting, camera perspective or heavy scan noise.
- **Metrics/rejection:** primary = mean per-family exact field rate over the three held-out rotated documents (WO-03, INV-03, MP-02), denominator each family's predeclared expected fields. Retain only for >=5-point mean gain, no new total/identifier error, no lost expected table row, and no field/cell regression on any clean raster control. Median end-to-end latency ratio must be <=1.10. Any incorrect page-order result, extra row or incomplete document rejects promotion. Record per-page angle error for diagnostics using transform metadata only after predictions are frozen; it is not the quality metric.
- **Smallest future execution:** 16 raster documents (8 image-only unrotated and 8 rotated), paired arms, three warm repeats under the common protocol; algorithm frozen on five development families before held-out access. No OCR execution now; a later CPU-only implementation/fixture check also needs its own assignment.
- **Resources/promotion:** CPU preprocessing plus the same qualified leased GPU and storage as baseline; capacities unknown. Promotion would add one bounded preprocessing stage with a no-op path and clean-document regressions. Real-scan benefit would require a later admitted scan corpus.

## H3 — smaller serving page windows reduce peak memory without losing cross-page content (rank 3; deferred)

- **Source/limitation:** the pinned project README exposes page-window scheduling and cautions about cross-page merges. Native inference is not evidence for custom SGLang scheduling. Actual wheel source behavior remains uninspected, so this card is conditional on Q0 qualifying that wheel and its effective flags.
- **Single treatment:** in base mode with scheduling enabled, change ONLY `SGLANG_UOCR_DOC_BASE_PAGE_WINDOW` from 10 to 2. Leave the gundam window unused/unchanged. This is upstream scheduling, not splitting documents into separate requests or implementing a new merge algorithm.
- **Vanilla baseline:** pinned custom `sglang-0.5.20.dev13+g75b9b06b02` wheel (advertised SHA in assessment; local digest and exact dependency build unresolved), same HF model revision, `SGLANG_UOCR_EANABLE_DOC_LIMIT=1`, base window 10 and crop_mode=False. Freeze a safe concurrency-1 Q0 launch configuration; do not copy the upstream 64-request example as a qualified 16-GB configuration. Preserve the upstream spelling EANABLE.
- **Controls/confounds:** identical whole-document requests, page order, renderer, payload token caps, shared-memory path, attention/kernel selection, postprocessing and cache policy. Fresh matched server processes for each arm because environment flags may be read at startup; exclude load/warmup identically. Track GPU memory baseline to distinguish KV reduction from allocator reuse. Use the same custom ngram/page guards in both arms; do not reuse native results.
- **Prediction:** smaller peak GPU memory on MP-02 (12 pages); possible loss of continuation rows or associations at 2-page boundaries. Shorter-window latency may increase; no quantitative upstream result is imported.
- **Metrics/rejection:** primary = (baseline peak allocated GPU bytes - treatment peak) / baseline peak for each successful multipage document, with reserved memory reported separately. Retain only if MP-02 median peak reduction >=10%, all expected cross-page row/identifier links in MP-01 and MP-02 remain exact (denominator all declared links), no new missing/extra row, and no lost fields, incomplete page, page-order error or truncation. Median elapsed ratio must be <=1.10. If both arms do not complete, report a capacity boundary; do not claim a paired memory improvement.
- **Smallest future execution:** MP-01 (4 pages) and MP-02 (12 pages), plus WO-01 and INV-01 single-page controls; three warm repeats per arm. MP-01 is development and MP-02 stays held out. A two-page corpus would not exercise window 10, hence the predeclared 12-page family.
- **Resources/promotion:** requires a fully qualified custom serving runtime, an owned local-only port/process/shared-memory directory and leased GPU, none currently allocated. Memory/storage needs unknown. Promotion cost is higher than H1/H2: worker-serving configuration and cross-page regression evidence, still no architectural changes.

Any failed hypothesis can be closed without blocking durable intake or ordinary OCR qualification. A threshold met on three held-out families supports only a small follow-up decision; it does not establish general maintenance-document performance. Do not retune on those families after a failed evaluation.
