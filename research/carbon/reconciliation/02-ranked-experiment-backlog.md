## 2. Common Paired Comparison Protocol (`E1`–`E3`)

1. **Frozen Inputs & Partition Discipline:** Use the materialized 8-family synthetic corpus (`evaluation/manifests/corpus-manifest.json`, `26 PDFs / 40 pages`: `dev = {F01, F02, F04, F07}`, `eval_holdout = {F03, F05, F06, F08}`). Because `eld-rd-carbon` authored the declarative source files, `eval_holdout` is a **fixed test partition**, not blind validation to its author. All code, prompts, parsers, and thresholds must be frozen using `dev` only without reading `evaluation/synthetic/expected/*` for `F03, F05, F06, F08`. Every derived variant (`v1-raster300`, `v2-skew`, `v3-hybrid`) remains strictly in its parent family and split.
2. **Engine & Budget Parity:** Never pool native `Transformers` and SGLang across an A/B pair, and never swap PDF renderers inside an ablation. Freeze generation budgets before held-out execution: `max_length=131072`, `max_new_tokens=min(8000 * page_count, remaining_context_budget)`, `max_page_tokens=20000`, `temperature=0.0` (greedy), `page_count_guard=True`, identical explicit `no_repeat_ngram_size` / `ngram_window` guards, and `save_results=False`. Any input exceeding context budget is recorded as an explicit unsupported/failed case, never silently truncated.
3. **Deterministic Scoring Rules:** Score against predeclared `expected/*.json` records (`printed_text` and `normalized_value`). Normalize Unicode NFC, line endings, and outer whitespace only; **never** auto-repair digits, strip leading zeros from identifiers (`WO-004192`, `0019-GFCI`), infer missing totals, or use an LLM judge. Currency values require exact normalized two-decimal (`0.01`) match. Missing, unmapped, or truncated expected items remain in the denominator as failures; invented extra fields/rows and violations of `expected_absences` are counted explicitly. Any post-`Q0` OOM, timeout, or truncated completion remains in the document denominator as a failed completion.
4. **Aggregation & Timing Protocol:** Report per-document counts first, then **equal-weight family means** (variants and repeated runs are correlated observations, never independent samples; make zero statistical-significance or population-generalization claims from 4 held-out families). For timing/memory under an owned GPU lease: run 1 excluded warmup + **3 interleaved warm repeats (`AB / BA / AB`)** at concurrency `1` with `torch.cuda.synchronize()` boundaries, logging stage wall times (gate/render/preprocess/prefill+decode/postprocess), peak allocated & reserved GPU bytes, and process RSS (cold-load logged separately; mark timing inconclusive if external WDDM GPU contention changes mid-run).

## 3. Ranked Falsifiable Experiment Cards (Maximum Three)

### Rank 1 — `E1`: Explicit Dynamic Tiling (`crop_mode=True`) vs. Global-View Base Mode (`crop_mode=False`) in Native `infer_multi`

- **Lineage:** Reconciled from `Astra H1` (`/001`) and `Carbon H-C2` (`/002`).
- **Source-grounded limitation:** Native `UnlimitedOCRForCausalLM.infer_multi` (`modeling_unlimitedocr.py` L1110–1123, documented in HF `README.md` L101–108) defaults `crop_mode=False`, letterbox-padding each page to a single `1024x1024` global image (`273` visual tokens/page, ~93 effective DPI on Letter), whereas single-page `infer` (L541) and upstream's benchmark client `infer.py` (L74) default to `crop_mode=True` (`gundam` tiling: `1024x1024` global view + up to `16` `640x640` local crops). Small 8.5-pt SKU codes, unit identifiers, negative signs, and currency decimals on dense invoices may suffer downsampling errors under `crop_mode=False`, while `crop_mode=True` multiplies visual prefill tokens (~5–10x) against native `_forward_dense` / `DynamicCache` memory and latency limits.
- **Proposed single treatment:** Call the **same** native `model.infer_multi` wrapper on all 8 clean originals (`v0-clean`, `8 PDFs / 12 pages`, rendered at fixed `300 DPI` via frozen `pypdfium2`), changing **only** `crop_mode=False` (baseline) to `crop_mode=True` (treatment) with fixed `base_size=1024`, `image_size=640`, `max_crops=16`, `save_results=False`. Using `infer_multi` explicitly on both 1-page and 3-page originals eliminates wrapper-selection confounding.
- **Controlled variables & remaining confounders:**
  - *Controlled:* Checkpoint/code (`04809669...`), `300 DPI` PNG bytes, prompt template, output token caps, ngram/page guards, `process_unlimitedOCR2.py`, and downstream field/table normalizer.
  - *Confounds to log:* Higher visual token counts reduce `remaining_context_budget` (log prompt vs. output token counts to confirm truncation does not masquerade as quality shift); tile boundary seams could duplicate cell tokens; `_forward_dense` SDPA prefill scales quadratically per chunk with visual sequence length $S$. Never automatically substitute sequential 1-page calls if multi-page `crop_mode=True` hits memory limits.
- **Predicted effect (unmeasured hypothesis):** Higher exact table-cell recall on dense invoices/packets (`F05`, `F06`, `F08`), higher prefill latency and peak GPU memory, neutral effect on sparse work orders.
- **Metrics, explicit denominators, and rejection criterion:**
  - *Primary quality metric:* `exact_matched_table_cells / total_expected_table_cells` per document, summarized by equal-weight family mean on the predeclared dense/multipage holdout subset `{F05, F06, F08}` and checked across all 4 holdouts `{F03, F05, F06, F08}`.
  - *Safety/integrity metrics:* `exact_matched_fields / total_expected_fields`, `preserved_cross_page_links / total_expected_links` (`F07`, `F08`), `correctly_ordered_adjacent_page_pairs / total_expected_page_pairs`, OOM/truncation count, and `median_doc_latency_treatment / median_doc_latency_baseline`.
  - *Rejection criterion:* **Reject `E1` for default promotion** unless **all** hold: (1) equal-weight family mean exact table-cell rate on held-out `{F05, F06, F08}` improves by **`>= +5.0` percentage points**; (2) **zero** individual holdout family (`F03, F05, F06, F08`) regresses on field or table-cell exact match; (3) **zero** new identifier, monetary-total, page-order, cross-page-link, truncation, or OOM failures occur; and (4) median per-document end-to-end latency ratio is **`<= 2.00x`**.
- **Smallest execution & promotion cost:** Paired runs on the `8` `v0-clean` originals (`4 dev` sanity + `4 eval_holdout` frozen test, 3 interleaved warm repeats) under one leased GPU session after `Q0`. Low promotion cost (single configuration flag + max-page guard in future worker).

### Rank 2 — `E2`: Conditional Non-Binarizing Projection-Variance Deskew vs. Uncorrected Raster Pass-Through

- **Lineage:** Reconciled from `Astra H2` (`/001`) and `Carbon H-C3` (`/002`).
- **Source-grounded limitation:** Native `_uocr_build_inputs` (`modeling_unlimitedocr.py` L531–580) resizes/pads pages without rotational correction, so `3°–4°` scanner skew misaligns horizontal invoice/checklist rows across vertical columns and warps horizontal table rules. Unconditional rotation or binarization degrades clean `0.0°` pages.
- **Proposed single treatment (frozen algorithm):** Insert **one** deterministic CPU deskew gate ahead of unchanged native `infer_multi(..., crop_mode=False, save_results=False)`:
  1. Compute an internal grayscale + Otsu thresholded foreground mask $M$ **solely for angle estimation** (never passed to OCR).
  2. Evaluate candidate angles $\theta \in [-5.0^\circ, +5.0^\circ]$ in exact `0.1°` steps (`101` candidates), computing horizontal row-projection variance $V(\theta) = \operatorname{Var}_y\!\big(\sum_x M_\theta(y, x)\big)$; select $\hat{\theta}$ maximizing $V(\theta)$ with smallest $|\theta|$ then positive-angle tie-break (never reading manifest rotation metadata).
  3. **Gate:** Trigger rotation **if and only if** $|\hat{\theta}| \ge 1.0^\circ$ **and** $V(\hat{\theta}) \ge 1.10 \cdot V(0.0^\circ)$ (`>= 10%` score improvement over `0.0°`).
  4. **No-op invariance:** When untriggered, pass the original RGB page bytes **byte-for-byte unchanged** (`0` pixel diffs).
  5. **Single resample:** When triggered, rotate the original 24-bit RGB page **once** by $-\hat{\theta}$ using `PIL.Image.Resampling.BILINEAR` with `expand=True` and constant white `(255, 255, 255)` fill.
- **Vanilla baseline:** Qualified native `infer_multi(..., crop_mode=False, save_results=False)` consuming the identical uncorrected raster inputs (`8` unrotated `v1-raster300` PDFs and `8` signed-skew `v2-skew` PDFs: `+4.0°` on odd families `F01, F03, F05, F07`; `-3.0°` on even families `F02, F04, F06, F08`). Holding `crop_mode=False` in both arms prevents stacking `E1` and `E2`.
- **Controlled variables & remaining confounders:**
  - *Controlled:* Model/code pin, `crop_mode=False`, `300 DPI` raster base pixels, prompts, token budgets, postprocessor, and scorer.
  - *Confounds to log:* Expanded white canvas after rotation changes input pixel dimensions before `1024x1024` letterbox resize (and would alter tile counts if `crop_mode=True` were used—log pixel dims and GPU memory explicitly); vertical rules or sparse checklists (`F03`) could perturb projection variance. Freeze exact tie/rounding code on `dev` (`F01, F02, F04, F07`) before touching `eval_holdout`.
- **Predicted effect (unmeasured hypothesis):** Improved field/table-cell exact match on rotated rasters (`v2-skew`), exact `0`-byte diff and `0` regressions on unrotated rasters (`v1-raster300`), modest CPU overhead.
- **Metrics, explicit denominators, and rejection criterion:**
  - *Primary quality metric:* Equal-weight family mean `exact_matched_fields / total_expected_fields` (and separately `exact_matched_table_cells / total_expected_table_cells`) across the `4` held-out skewed fixtures (`F03, F05, F06, F08` `v2-skew`).
  - *Invariance & cost metrics:* `untriggered_clean_pages / total_clean_v1_pages` (`12` pages across `8` `v1-raster300` docs), clean-control paired delta, post-freeze diagnostic $|\hat{\theta} - \theta_{\text{true}}|$, and `median_doc_latency_treatment / median_doc_latency_baseline`.
  - *Rejection criterion:* **Reject `E2` for promotion** if **any** occurs: (1) **any** false trigger or non-identical input bytes on clean unrotated `v1-raster300` pages (`untriggered_clean_pages < 12`), or any field/cell regression on clean controls; (2) equal-weight mean exact-field gain on held-out skewed fixtures `{F03, F05, F06, F08}` is **`< +5.0` percentage points**; (3) any new monetary-total, identifier, table-cell, missing-row, cross-page-link, page-order, truncation, or OOM error occurs; or (4) median end-to-end latency ratio exceeds **`1.10x`**.
- **Smallest execution & promotion cost:** `16` raster PDFs (`8` `v1-raster300` + `8` `v2-skew`, `24` pages total), paired arms with 3 warm repeats after freezing estimator code on `dev`. Low promotion cost (bounded CPU pre-stage with byte-identical no-op fast path; real scanner benefit still requires later real scan fixtures).

### Rank 3 — `E3`: Two-Stage Conservative Zero-Image-Abstaining PDF Text-Layer Routing vs. Unconditional VLM OCR

- **Lineage:** Reconciled from `Carbon H-C1` (`/002`) with `Astra /003` strict zero-image abstention and hybrid counterexample gate integrated.
- **Source-grounded limitation:** Upstream client pipelines rasterize every PDF page into RGB bitmaps for VLM decoding, even when contractor/accounting software exported clean born-digital vector text. However, as established in `Astra /003`, Carbon's initial `< 15%` image-area heuristic is unsafe: a small (`4%–6%` area) embedded raster note or holdover stamp on an otherwise vector page carries critical operational data invisible to PDF text extraction, and vector streams can also suffer reading-order or unmapped-glyph defects.
- **Proposed single pipeline treatment (two-stage gated):**
  - **Strict Abstaining Gate (all pages $1..P$ must pass every check, else the entire document abstains to unchanged qualified VLM OCR):**
    1. **Zero embedded images (`image_xobject_count == 0`):** Zero `/Subtype /Image` XObjects (and zero inline `BI..ID..EI` images) anywhere in page `/Resources` or nested `/Form` XObjects—no permissive logo-area exception.
    2. **Clean character mapping:** Printable non-whitespace characters $\ge \tau_{\text{chars}}$ per page (calibrated on `dev` only), zero `U+FFFD` replacement characters, zero unmapped CID/glyphs, and all text bounding boxes within visible `MediaBox`/`CropBox` bounds with positive font size (rejecting off-page/zero-size hidden text).
    3. **Deterministic coordinate & table extraction:** Sort vector spans by `(page, y_bucket, x_min)` using PDF coordinates and map into the exact same downstream schema normalizer used by VLM postprocessing, tagging `source_mode: "pdf_text_layer"` vs `"ocr_vlm"`.
  - **Mandatory Stage Gate:**
    - **Stage 3A (CPU-Only Feasibility & Counterexample Gate — zero GPU required):** Freeze gate + coordinate extractor on `dev` (`F01, F02, F04, F07` `v0-clean`, `v1-raster300`, and hybrid `SYN-WO-02-v3-hybrid-note`), then evaluate once on `eval_holdout` (`F03, F05, F06, F08` `v0-clean`, `v1-raster300`, and hybrid `SYN-MP-02-v3-hybrid-stamp`). If Stage 3A misroutes **any** raster or hybrid page or misses expected fields/cells on `dev`, **reject `E3` immediately on CPU before allocating any GPU time.**
    - **Stage 3B (Paired End-to-End Comparison vs. Unconditional Qualified VLM OCR):** Only if Stage 3A passes, compare `[strict gate + coordinate extractor + fallback VLM]` against unconditional qualified native `infer_multi` (`save_results=False`) across `v0-clean`, `v1-raster300`, and `v3-hybrid` (`18 PDFs / 28 pages`).
- **Metrics, explicit denominators, and rejection criterion:**
  - *Safety denominator:* `misrouted_non_digital_pages / total_designated_non_digital_pages` across all `v1-raster300` (`12p`) and `v3-hybrid` (`4p`, specifically testing `< 8%`-area raster addenda alongside rich vector text).
  - *Correctness & latency metrics:* Paired per-document `exact_matched_fields / total_expected_fields` and `exact_matched_table_cells / total_expected_table_cells`, invented extra fields/rows, and `median_doc_latency_routed / median_doc_latency_vlm` on routed clean holdouts (including full gate + extraction + normalization wall time).
  - *Rejection criterion:* **Reject `E3`** if **any** occurs: (1) `misrouted_non_digital_pages > 0` on `dev` or `eval_holdout`; (2) `routed_clean_holdout_docs == 0` (empty routed set yields no positive claim); (3) **any** routed document in `eval_holdout` exhibits a negative paired field or table-cell correctness delta (`matched_treatment < matched_vlm`), new omission, or invented extra field/row; or (4) in Stage 3B, median end-to-end latency reduction across routed clean holdout documents is **`< 50.0%`** (`latency_ratio > 0.50x`).
- **Smallest execution & promotion cost:** Stage 3A runs on CPU only (`0` GPU); Stage 3B reuses baseline VLM runs on `v0-clean` / `v1-raster300` plus `2` `v3-hybrid` controls under one leased GPU session. Medium promotion cost (coordinate table extractor requires careful layout regression coverage, and strict zero-image abstention conservatively routes vendor PDFs containing raster logos to VLM OCR).
